마스터 데이터 관리

연차 신청에 쓰이는 시간대와 결재·백업 같은 시스템 설정을 한곳에서 다룹니다.

승인 워크플로우 — 현재: {% if is_approval_required %}켜짐 (결재 필요){% else %}꺼짐 (즉시 승인){% endif %}

꺼짐: 사원이 신청하면 바로 «승인됨»으로 기록됩니다.
켜짐: 신규 신청은 «결재 대기»로 들어갑니다. 관리자나 팀장이 대시보드 또는 타임라인에서 결재 처리합니다.

* PM(프로젝트 매니저) 본인의 연차 신청은 설정과 관계없이 항상 자동 승인됩니다.
* 팀장은 소속 팀원만 결재 가능하며, 본인 신청 건에 대한 자가 승인은 불가능합니다.

캘린더 공유 범위 설정 — 현재: {% if company_calendar_visible %} 프로젝트 전체 공유 {% elif team_calendar_visible %} 소속 팀원 공유 {% else %} 공유 안 함 (본인 전용) {% endif %}

일반 사원 및 팀장이 조회할 수 있는 연차 캘린더의 범위를 지정합니다.

시간 정책 설정 (30분 단위 선택)

입력 제어용 최소 단위입니다. 실제 차감은 선택 구간에서 점심시간 제외 후 계산됩니다.

~
~

• 입력 시각은 단위 경계만 가능하나, 하루 전체 신청을 위해 업무 종료 시각은 예외로 허용됩니다.

• 설정 단위보다 짧은 신청이나, 점심시간에 완전히 포함되어 실제 차감 시간이 0시간인 신청은 제한됩니다.

표시 이름(브랜딩)

공식 이름: 제목·푸터·상단 부제(긴 풀네임)

상단 짧은 이름: 상단 바 굵은 글자 (비우면 공식과 동일)

파란 배지: 왼쪽 네모 상자 안 (최대 24자)

데이터베이스 수동 백업

백업 파일은 var/data/backup/ 아래에 날짜·시각이 붙은 이름으로 저장됩니다.

💡 운영 메모

  • 정책 변경 전후로 수동 백업을 권장합니다.
  • 복구 리허설은 운영 복제 DB에서 먼저 확인합니다.
  • 운영 절차 상세는 `docs/1-2_유지보수_가이드`를 참고합니다.

ℹ️ 운영/상태 통합 안내

⏱️ 시간 정책 원칙

마스터 설정에 따른 연차 신청의 시간 계산 및 제약 조건입니다.

  • 연차 신청은 시작/종료 시각 기반으로 1건의 스냅샷으로 저장됩니다.
  • 입력 시각은 정책 단위 경계(30/60/120분)만 허용됩니다. (단, 하루 전체 신청 시 업무 종료 시각은 예외 허용)
  • 신청 구간이 정책 단위보다 짧거나 점심시간에 완전히 포함되어 실제 차감 시간이 0시간이면 신청이 제한됩니다.
  • 설정 단위는 입력 제어 기준이며, 실제 차감은 선택 구간에서 점심시간 제외 후 계산됩니다.
  • 하루 총 사용시간은 대시보드 및 캘린더에서 자동으로 합산하여 표시합니다.

📋 연차 신청 상태 설명

각 신청 건의 처리 상태를 뜻하며, 상태에 따라 집계(사용/잔여시간) 반영 여부가 결정됩니다.

  • 결재 대기: 결재 전 상태입니다. 아직 최종 확정되지 않은 대기 신청입니다.
  • 승인됨: 결재가 완료되어 연차 사용으로 최종 확정되었으며, 사용량에 반영됩니다.
  • 반려: 승인 거절된 상태입니다. 사용 시간 및 잔여 연차 계산에서 제외됩니다.
  • 신청 취소: 기존 신청을 철회·무효 처리한 상태입니다. 사용 시간 및 잔여 연차 계산에서 제외됩니다.
