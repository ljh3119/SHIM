마스터 데이터 관리

연차 신청 시간대와 결재·백업 등 시스템 설정을 관리합니다.

승인 워크플로우 — 현재: {% if is_approval_required %}켜짐 (결재 필요){% else %}꺼짐 (즉시 승인){% endif %}

꺼짐: 사원이 신청하면 바로 «승인됨»으로 기록됩니다.
켜짐: 신규 신청은 «결재 대기»로 들어가며 관리자나 팀장이 승인 처리합니다.

* PM 본인의 연차 신청은 항상 자동 승인됩니다.
* 팀장은 소속 팀원만 결재 가능하며 자가 승인은 불가합니다.

캘린더 공유 범위 설정 — 현재: {% if company_calendar_visible %} 프로젝트 전체 공유 {% elif team_calendar_visible %} 소속 팀원 공유 {% else %} 공유 안 함 (본인 전용) {% endif %}

일반 사원 및 팀장이 조회할 수 있는 연차 캘린더의 범위를 지정합니다.

시간 정책 설정 (30분 단위 선택)

입력 제어용 최소 단위입니다. 240분(반일) 설정 시 전일 및 표준 반차(0.5일)로만 신청됩니다.

~

기본값은 12:00~13:00입니다. 미사용하면 09:00~18:00 전일 신청은 9시간으로 계산됩니다.

~

• 입력 시각은 단위 경계만 가능하나, 전일 신청을 위해 업무 종료 시각은 예외 허용됩니다.

• 설정 단위보다 짧거나 점심시간에 완전히 포함되어 실제 차감 시간이 0시간인 신청은 제한됩니다.

표시 이름 (브랜딩)

공식 이름: 타이틀·푸터·상단 부제

상단 짧은 이름: 헤더 굵은 텍스트 (공란 시 공식과 동일)

마크 배지: 로고 배지 내 텍스트 (최대 24자)

데이터베이스 수동 백업

백업 파일은 var/data/backup/ 아래에 일시가 포함되어 저장됩니다.

운영 메모

  • 정책 변경 전후로 수동 백업을 권장합니다.
  • 복구 리허설은 운영 복제 DB에서 먼저 확인합니다.
  • 운영 절차 상세는 `docs/1-2_유지보수_가이드`를 참고합니다.

운영 / 상태 안내

시간 정책 원칙

연차 신청 시간 계산 및 제약 조건

  • 연차 신청은 시작/종료 시각 기반으로 1건의 스냅샷으로 저장됩니다.
  • 입력 시각은 정책 단위 경계(30/60/120분)만 허용됩니다.
  • 신청 구간이 점심시간에 완전히 포함되어 실제 차감 시간이 0시간이면 신청이 제한됩니다.
  • 설정 단위는 입력 제어 기준이며 실제 차감은 점심시간 제외 후 계산됩니다.
  • 하루 총 사용시간은 캘린더에서 자동으로 합산 표시됩니다.

연차 신청 상태 설명

상태에 따라 사용 및 잔여 연차 반영 여부 결정

  • 결재 대기: 아직 최종 확정되지 않은 대기 신청입니다.
  • 승인됨: 결재가 완료되어 연차 사용으로 최종 확정되었습니다.
  • 반려: 승인 거절된 상태로 잔여 연차에서 차감되지 않습니다.
  • 신청 취소: 철회·무효 처리된 상태로 연차 계산에서 제외됩니다.
