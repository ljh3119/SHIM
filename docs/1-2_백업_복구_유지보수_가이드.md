# 백업/복구/유지보수 가이드

운영 중 장애를 줄이기 위한 **실무 최소 기준** 문서입니다.

## 1) 반드시 백업할 것

- DB 파일: `var/data/shim_internal.db` (가장 중요)
- 백업 결과물: `var/data/backup/*.bak`
- 운영 문서: `README.md`, `docs/`, `portable/README_PORTABLE.md`

## 2) 권장 주기

- 일 1회 백업
- 주간 백업 4주 보관
- 월간 백업 6개월 보관

## 3) 백업 방법

### 방법 A: 관리자 화면

- `관리자 > 마스터 관리 > DB 백업 생성`

### 방법 B: 스크립트

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\scripts\backup_db.ps1
```

## 4) 복구 절차 (공통)

```powershell
# 앱/컨테이너 중지 후
Copy-Item .\var\data\backup\shim_internal_YYYYMMDD_HHMMSS.bak .\var\data\shim_internal.db -Force
# 앱/컨테이너 재기동
```

윈도우 탐색기 수동 복구도 가능합니다(결과 동일).

1. 앱/컨테이너를 먼저 완전히 종료합니다.
2. `var/data/shim_internal.db`를 `shim_internal.db.old` 등으로 먼저 보관합니다.
3. `var/data/backup`의 `.bak` 파일을 `shim_internal.db`로 이름 변경합니다.
4. 이름 변경한 파일을 `var/data` 폴더에 복사/덮어쓰기 합니다.
5. 앱/컨테이너를 재기동하고 로그인/조회가 정상인지 확인합니다.

참고:

- `.bak`는 백업 구분용 확장자이며 내부 포맷은 SQLite DB와 동일합니다.
- 실행 중 덮어쓰기는 파일 잠금/손상 위험이 있어 반드시 중지 후 진행합니다.

Docker 기준:

```powershell
docker compose -f infra/docker/docker-compose.yml down
Copy-Item .\var\data\backup\shim_internal_YYYYMMDD_HHMMSS.bak .\var\data\shim_internal.db -Force
docker compose -f infra/docker/docker-compose.yml up -d
```

Docker 운영 기동 전에는 운영용 JWT 서명키(`SHIM_SECRET_KEY`)를 설정합니다. 이 값은 로그인 쿠키 위조를 막기 위한 비밀키입니다.

권장 방식은 `.env.example`을 `.env`로 복사한 뒤, 긴 랜덤 문자열로 바꾸는 것입니다. 실제 `.env` 파일은 운영 비밀값이므로 문서, 채팅, 저장소에 공유하지 않습니다.

```powershell
Copy-Item .\.env.example .\.env
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))
```

생성된 값을 `.env`의 `SHIM_SECRET_KEY=` 뒤에 붙여 넣습니다.

```env
SHIM_SECRET_KEY=여기에_생성한_긴_랜덤_문자열
```

그 뒤 Docker를 기동합니다.

```powershell
docker compose -f infra/docker/docker-compose.yml up -d
```

참고:

- `SHIM_SECRET_KEY`를 설정하지 않아도 앱은 기본값으로 실행됩니다.
- 다만 기본값은 운영 보안에 적합하지 않으므로 실제 운영에서는 반드시 `.env`에 운영용 값을 지정합니다.
- 값을 바꾸면 기존 로그인 세션은 풀릴 수 있으며, 다시 로그인하면 됩니다.

## 5) 정기 점검 체크

- [ ] 로그인/대시보드 접속 정상
- [ ] 최근 데이터 저장/조회 정상
- [ ] 디스크 용량 및 백업 파일 누적 확인
- [ ] 승인 설정 상태(`is_approval_required`) 확인
- [ ] `.env`의 `SHIM_SECRET_KEY`가 기본값이 아닌 운영용 문자열인지 확인
- [ ] 기본 관리자(`admin / 0000`) 최초 로그인 후 비밀번호 변경 여부 확인(비밀번호 본문 기록 금지)
- [ ] 재기동 후 시간대 활성/비활성 및 차감 시간이 운영자 설정대로 유지되는지 확인
- [ ] 복구 DB 기동 후 `leaves` 조회 인덱스가 자동 적용되는지 확인

## 6) 장애 대응 순서

1. 증상 확인(로그인/화면/응답)
2. 로그 확인(앱 로그 또는 `docker compose -f infra/docker/docker-compose.yml logs`)
3. DB 파일 존재/권한 확인
4. 최근 변경점 확인
5. 필요 시 최신 정상 백업으로 복구

## 7) 포터블 운영 메모

- 표준 실행: `run_portable.bat`
- 표준 종료: `stop_portable.bat`
- 배포 단위: `artifacts/dist/SHIM_Portable` 폴더 전체
- 최초 1회 실행 시 `SHIM_SECRET_KEY`를 입력하면 `data/secret.key`로 저장되며, 이후 자동 사용됨
- `data/secret.key`를 분실하면 기존 로그인 토큰이 무효화될 수 있으므로 DB 백업과 함께 별도 안전 보관 권장
- 다른 PC로 이관 시 `shim_internal.db`와 `secret.key`를 같이 옮겨야 기존 세션 정책을 일관되게 유지 가능

관련 정책/릴리즈 기준:

- `docs/2-1_운영_릴리즈_통합_산출물.md`
