# 백업, 복구 및 유지보수 가이드 (Maintenance Guide)

운영 중 발생할 수 있는 데이터 손실을 방지하고, 시스템 장애 시 신속하게 복구하기 위한 기술 표준 문서입니다.

---

## 0. 최초 사업장 시간대 설정

- 한 인스턴스는 하나의 사업장 시간대만 사용합니다. Docker 배포에서는 `infra/docker/.env.example`을 `.env`로 복사한 뒤 IANA 이름을 설정합니다.

  ```dotenv
  SHIM_TIMEZONE=Asia/Seoul
  ```

- 미설정 시 기본값은 `Asia/Seoul`입니다. 해외 신규 배포 예시는 `America/New_York`이며 실행 중에는 바뀌지 않으므로 변경 후 서비스를 재기동해야 합니다.
- Docker 컨테이너 OS는 `TZ=UTC`로 유지합니다. 서버 OS·브라우저 시간대는 SHIM 업무 시간에 영향을 주지 않습니다.
- 잘못된 이름이면 시작 로그에 `Invalid SHIM_TIMEZONE: <설정값>`이 출력되고 기동이 중단됩니다. IANA 이름을 수정한 뒤 재기동하십시오.
- 기존 SQLite 데이터는 마이그레이션하지 않습니다. 저장값은 계속 Naive UTC이고 화면·감사·엑셀만 사업장 시간대로 표시됩니다.

## 💾 1. 데이터 백업 (Backup)

### 백업 대상 (Critical Assets)
- **운영 데이터베이스**: `var/data/shim_internal.db` (가장 핵심적인 데이터)
- **보안 설정**: `.env` 파일 (JWT 서명키 및 환경 변수)
- **정기 백업 산출물**: `var/data/backup/*.bak` 파일들

### 권장 백업 정책
- **일간(Daily)**: 매일 업무 종료 후 1회 (30일분 보관)
- **주간(Weekly)**: 매주 금요일 업무 종료 후 1회 (12주분 보관)
- **월간(Monthly)**: 매월 말일 1회 (6개월분 보관)

### 백업 수행 방법
- **방법 A (UI)**: 관리자 로그인 후 `[마스터 관리 > DB 백업 생성]` 클릭
- **방법 B (CLI)**: PowerShell에서 수동 스크립트 실행
  ```powershell
  .\tools\scripts\backup_db.ps1
  ```

자동 백업은 임시 파일 작성 → `PRAGMA quick_check` → 원자적 파일 교체 순서로 완료됩니다. 손상된 `.bak`는 `.invalid`로 격리되어 보관 개수와 회전 대상에서 제외됩니다. 회전 삭제에 실패한 파일은 그대로 남으며, 대시보드의 백업 개수는 최종 재검사에서 확인된 복구 가능 백업 수를 표시합니다.

## 🚑 2. 시스템 복구 (Recovery)

### 시나리오: DB 파일 손상 시 복구 절차
*SHIM은 기동 시 데이터베이스 파일 정합성을 자동으로 자가 검사(`PRAGMA quick_check;`)합니다. 만약 시작 로그에 `[SHIM DATABASE CORRUPT WARNING]`이 노출된다면 데이터베이스 물리 구조가 비정상적으로 오염된 것이므로 아래 복구 절차를 수행하여 이전 백업본으로 교체해야 합니다.*

1.  **서비스 중지**: 실행 중인 서버 또는 Docker 컨테이너를 중지합니다.
    ```powershell
    docker compose -f infra/docker/docker-compose.yml down
    ```
2.  **기존 파일 백업**: 현재의 `var/data/shim_internal.db` 파일을 `shim_internal.db.old`로 이름을 변경하여 보관합니다.
3.  **최신 백업본 복사**: `var/data/backup/` 폴더에서 가장 최근의 정상적인 `.bak` 파일을 찾습니다.
4.  **파일 교체**: 해당 파일을 `var/data/` 폴더로 복사하고 이름을 `shim_internal.db`로 변경합니다.
    ```powershell
    Copy-Item .\var\data\backup\shim_internal_YYYYMMDD_HHMMSS.bak .\var\data\shim_internal.db -Force
    ```
5.  **서비스 재개**: 서버 또는 컨테이너를 다시 기동합니다.
    ```powershell
    docker compose -f infra/docker/docker-compose.yml up -d
    ```

> [!IMPORTANT]
> **DB 암호화 활성화 시 복구/이전 주의사항**:
> 만약 환경변수 `SHIM_SECRET_KEY`를 명시적으로 부여했거나, 데이터 폴더에 수동으로 `secret.key`를 생성하여 PII 개인정보 컬럼 암호화를 활성화한 경우, 새로운 기기나 환경으로 이전·복구할 때 `var/data/shim_internal.db` 파일뿐만 아니라 **동일 폴더의 `secret.key` 파일(또는 환경변수 값)도 함께 세트로 복사**해야 복호화가 작동합니다. 키가 없거나 다른 경우 데이터가 정상적으로 해독되지 않습니다.
>
> [!WARNING]
> **평문 모드와 암호화 모드 간 사후 전환 절대 불가 (Fail-Fast)**:
> 데이터베이스 기동 시의 보안 상태(평문/암호화)는 데이터베이스 내부 메타데이터에 키 해시 스냅샷으로 안전하게 잠금(Lock) 처리됩니다.
> 기존 평문 모드로 운영되던 데이터베이스에 사후적으로 암호키를 주입하거나, 반대로 암호화 운영 상태에서 키 설정을 누락하여 평문 모드로 구동하는 것은 **검색/필터링 기능 오작동 및 데이터 오염을 예방하기 위해 시스템 기동이 원천 차단(Application Startup Failed)됩니다.**
> 모드를 완전히 변경하려는 경우, 반드시 기존 데이터베이스 파일을 백업 후 삭제한 상태에서 새로운 모드로 최초 구동하여 새로 정비해야 합니다.

## 🔐 3. 보안 및 운영 유지보수

### 관리자 비밀번호 분실 시 복구 (Emergency Reset)
비밀번호를 분실하여 로그인이 불가능한 경우, 전용 스크립트를 통해 `admin` 계정의 비밀번호를 즉시 `0000`으로 초기화할 수 있습니다. 운영 환경에 따라 아래 절차를 따르십시오.

#### 1. Docker 환경 (운영 서버)
1. 운영 서버(Linux/Windows)의 터미널 또는 PowerShell을 엽니다.
2. 다음 명령어를 실행하여 실행 중인 컨테이너 내부에서 스크립트를 가동합니다. (컨테이너 이름이 `shim`인 경우)
   ```bash
   docker exec -it shim python tools/scripts/emergency_reset_admin.py
   ```
3. `[성공] 'admin' 계정의 비밀번호가 '0000'으로 초기화되었습니다.` 메시지를 확인합니다.

#### 2. 포터블 환경 (독립형 PC / NAS)
1. SHIM 프로그램이 위치한 폴더(`SHIM_Portable`)를 엽니다.
2. 폴더 빈 공간에서 `Shift + 우클릭` 후 **'여기에 PowerShell 창 열기'**(또는 터미널 열기)를 선택합니다.
3. 다음 명령어를 실행합니다.
   ```powershell
   # 빌드된 포터블 실행 파일 실행 시
   .\SHIM_Portable.exe --reset-admin

   # 또는 소스 실행 시
   python portable/shim_portable.py --reset-admin
   ```
4. 성공 메시지 확인 후 브라우저에서 `admin / 0000`으로 로그인합니다.

**⚠️ 주의사항**: 초기화 완료 후 보안을 위해 즉시 시스템에 로그인하여 **새로운 비밀번호로 변경**하십시오. 이 작업 이력은 감사 로그에 '시스템 강제 초기화'로 영구 기록됩니다.

### JWT 서명키 및 DB 암호화 비밀키 통합 관리
- SHIM은 시스템 보안을 위해 **단 하나의 보안 비밀키(Secret Key)**를 사용하지만, 이 키는 내부적으로 **두 가지 다른 보안 역할**(JWT 서명 및 PII 암호화)을 수행합니다. 자세한 작동 원리와 포터블 ↔ Docker 간 데이터 이관 가이드는 아래 [3.2 보안 비밀키 통합 관리 및 복구/이전 가이드](#32-보안-비밀키-통합-관리-및-복구이전-가이드) 섹션을 참고하십시오.
- **키 유출 시**: 즉시 키를 재생성하고 서버를 재기동하십시오. 기존 사용자의 로그인 세션은 즉시 만료됩니다.

## 🔐 3.2 보안 비밀키(Secret Key) 통합 관리 및 복구/이전 가이드

SHIM은 비밀키 설정값에 따라 개인정보 데이터를 대칭 암호화하거나 평문으로 가볍게 저장하는 두 가지 유연한 방식을 제공합니다.

1. **JWT 로그인 세션 서명**: 로그인 토큰의 변조 방지를 위해 사용됩니다. **(상시 작동)**
2. **PII 데이터베이스 컬럼 암호화**: 사원 실명 및 연차 사유 등을 DB 내부에서 암호화(`Fernet` 대칭키 방식)하여 보호합니다. **(선택적 작동)**
   - **활성화 조건**: 환경변수 `SHIM_SECRET_KEY`에 사용자 정의 키를 등록했거나, 포터블 구동 시 사용자가 직접 비밀키를 수동 입력하여 저장한 경우에만 암호화가 활성화됩니다.
   - **평문 저장 폴백**: 사용자가 키를 입력하지 않아 시스템이 무작위 키를 임의 생성한 경우(키 파일 첫머리에 `# AUTO-GENERATED` 주석 존재 시), 이식성을 극대화하기 위해 암호화는 비활성화되고 평문(Plaintext)으로 저장됩니다.

---

### 1. 환경별 초기 기동 시 보안키 생성 및 적용 방식

#### 📦 포터블 (Portable) 환경
- **구동 방식**: `SHIM_Portable.exe` 최초 기동 시 작동
- **동작 흐름**:
  1. `data/secret.key` 파일이 없는 경우, 콘솔 창에 사용자 입력 프롬프트가 표시됩니다.
  2. **사용자가 키 입력 시**: 입력한 텍스트가 `data/secret.key`에 저장되며 **개인정보 암호화가 활성화**됩니다. (다른 시스템이나 소켓 연동 시 동일한 키를 입력하여 동기화 가능)
  3. **미입력(엔터) 시**: 보안 64자리 무작위 키를 생성하여 `data/secret.key`에 `# AUTO-GENERATED` 헤더와 함께 저장하며, **개인정보 암호화는 비활성화(평문 저장)** 상태로 유지됩니다.

#### 🐳 Docker 환경
- **구동 방식**: `docker compose up -d` 기동 시 작동
- **동작 흐름**:
  1. `.env` 파일 내 `SHIM_SECRET_KEY` 값을 읽어 컨테이너 내부 환경변수로 주입합니다.
  2. **`.env`에 키를 지정한 경우**: 해당 키를 SHA-256 해시화하여 대칭키를 파생하고 **DB 암호화를 활성화**합니다.
  3. **`.env` 키가 없거나 기본값인 경우**: 데이터 볼륨 내 `secret.key` 파일을 읽어 감지하며, 파일도 없는 경우 무작위 64자리 랜덤 키를 자동으로 생성하여 파일에 기재합니다. 이 경우 **DB 암호화는 비활성화(평문 저장)** 됩니다.

### 2. 환경 간 데이터 이관 및 마이그레이션 (포터블 ↔ Docker)

포터블 환경에서 사용하던 데이터와 설정을 그대로 Docker 환경의 서버로 이관하거나, 반대의 경우 아래 절차를 통해 **비밀키 정합성을 유지하며 즉시 이관**할 수 있습니다.

#### 💡 파일 복사 방식 마이그레이션 (가장 안전하고 권장하는 방법)
*Docker 버전도 환경변수가 없으면 볼륨 내 `secret.key` 파일을 자동으로 읽어 들이므로, 포터블과 Docker 간에 키와 DB 파일을 동일하게 복사하는 것만으로 완벽한 이관이 보장됩니다.*

1. **데이터 백업**:
   - 기존 운영 환경(예: 포터블 폴더의 `data` 폴더)에서 다음 두 파일을 복사합니다.
     - 🗄️ **`shim_internal.db`** (데이터베이스 파일)
     - 🔑 **`secret.key`** (보안 비밀키 파일)
2. **대상 서버로 복사**:
   - 새롭게 이관하여 구동할 대상 서버의 볼륨 마운트 데이터 경로(예: Docker 프로젝트 루트의 `./var/data/` 디렉토리)에 복사한 두 파일을 그대로 붙여넣습니다.
3. **환경변수 조율**:
   - 새 서버의 `.env` 파일 내 `SHIM_SECRET_KEY`는 설정하지 않고 비워둡니다. (환경변수가 지정되어 있으면 파일 키 감지를 우회하여 데이터 해독 실패가 발생하므로 반드시 비워두어야 합니다.)
4. **컨테이너 기동**:
   - `docker compose up -d`를 통해 실행하면, Docker가 복제된 `secret.key`와 데이터베이스를 스스로 감지하고 해독하여 이전 운영 상태 그대로 완벽히 서비스를 재개합니다.

> [!CAUTION]
> **암호화 활성화 상태 이관 시 비밀키 유실 경고**:
> 개인정보 암호화가 활성화된 데이터베이스(`shim_internal.db`)는 **최초 데이터 암호화에 쓰인 비밀키(secret.key 텍스트)가 없으면 해독이 불가능**합니다. 기기 이전 시 반드시 `secret.key` 파일 또는 `.env`의 환경변수 키값을 백업 세트로 함께 이전하십시오.
>
> **비밀키 일관성 위반에 따른 기동 강제 차단**:
> 기존 데이터베이스의 모드(평문/암호화) 혹은 설정된 키 값과 현재 주입된 비밀키가 일치하지 않는 경우, 데이터 오염을 막기 위해 서버가 기동을 즉시 거부하며 로그에 `[SHIM CRITICAL ERROR]`를 출력하고 종료됩니다. 임의로 키를 변경하지 마시고 `.env` 설정이나 `secret.key` 파일을 이전 환경의 키와 완벽하게 일치시킨 뒤 재기동해 주십시오.

## 🛠️ 4. 장애 대응 프로세스

3.  **상태 점검**: DB 파일 무결성 및 네트워크 포트(8000) 점검

## 6. 장기 가동 운영 권고

- **백업과 용량**: 자동 백업 결과와 보존 개수를 정기적으로 확인하고, DB·백업 경로의 남은 디스크 공간을 감시합니다.
- **포터블 호스트**: 장기 운영 PC는 절전·최대 절전을 끄고 OS 시간 동기화를 유지합니다. 앱의 사업장 시간대는 OS 설정이 아니라 `SHIM_TIMEZONE`으로 고정합니다.
- **Docker 시간대**: 컨테이너 OS는 이미지에서 UTC로 고정하고, 애플리케이션은 `SHIM_TIMEZONE`을 사용합니다. Compose에서 `TZ`를 중복 지정할 필요가 없으며 한 인스턴스는 하나의 IANA 사업장 시간대만 지원합니다.
- **로그 보존**: 기본 Compose는 별도 파일 로그를 만들지 않습니다. 장기 보존이 필요한 운영 환경에서만 Compose override에 로그 순환(`max-size`, `max-file`)을 추가합니다.
- **부하 점검**: 대규모 데이터 도입 전 `tools/scripts/performance_rehearsal.py`로 대상 장비에서 예행 점검합니다. 완료된 측정값과 릴리스 증적은 [운영/릴리즈 통합 산출물](2-1_운영_릴리즈_통합_산출물.md)에 기록합니다.

### 6.1 알림 정리 실패 해석

알림은 SQLite 잠금 시간을 줄이기 위해 청크별로 삭제·커밋합니다. 모든 청크와 운영 메트릭 저장이 성공한 경우에만 마지막 성공 시각을 갱신합니다. 중간 실패 전 일부 삭제는 남을 수 있으며 실패 시 기존 성공 시각을 유지하므로, 로그의 실패 원인을 확인한 뒤 다음 스케줄 또는 재기동으로 재시도하십시오.

### 6.2 운영 환경 변수 예시

```yaml
services:
  shim:
    env_file:
      - .env
    environment:
      SHIM_TIMEZONE: ${SHIM_TIMEZONE:-Asia/Seoul}
      SHIM_SECRET_KEY: ${SHIM_SECRET_KEY}
```

운영 시간대 설정은 `SHIM_TIMEZONE` 하나만 사용합니다. 값이 잘못된 IANA 이름이면 데이터 처리 전에 기동을 중단합니다.
