# SHIM 시스템 상세 설계서 (Technical Specification)

**애플리케이션 버전**: 1.3.3 (진행 중)  
**최종 업데이트**: 2026-05-13  
**문서 성격**: 시스템 아키텍처, 데이터 모델 및 비즈니스 규칙에 대한 기술적 표준 정의

---

## 1. 아키텍처 개요 (Architecture Overview)

SHIM은 폐쇄망 환경의 제약 조건을 극복하면서도 사용자에게 현대적인 웹 경험을 제공하도록 설계되었습니다.

- **Monolithic 구조**: FastAPI를 중심으로 정적 자산, 템플릿, 비즈니스 로직, 데이터 접근 계층을 단일 프로세스에서 처리합니다.
- **데이터 저장소**: 별도의 DBMS 설치가 필요 없는 SQLite를 사용하며, 동시성 향상을 위해 WAL(Write-Ahead Logging) 모드를 사용합니다.
- **보안 모델**: JWT 기반의 상태 비저장(Stateless) 인증을 수행하며, 토큰은 HttpOnly 쿠키에 저장되어 XSS 공격을 방지합니다.

---

## 2. 데이터 모델 (Data Schema)

### 2.1 핵심 엔티티
- **Users**: 조직원 정보 및 잔여 연차 관리. `role` 필드를 통한 RBAC 제어.
- **Leaves**: 연차 신청 기록. 신청 시점의 정책 스냅샷(`snapshot_*`) 보관.
- **AuditLogs**: 관리자 행위 및 시스템 설정 변경 이력 추적.
- **SystemSettings**: 전사 승인 정책, 시간 단위, 업무 시간 범위 등 전역 설정.

### 2.2 인덱스 설계 (Performance)
조회 성능 최적화를 위해 다음 복합 인덱스를 적용합니다.
- `idx_leaves_user_date`: `(user_id, date)` - 개인별 사용 현황 조회
- `idx_leaves_year_date`: `(year, date)` - 전사 연도별 캘린더 조회
- `idx_leaves_created`: `(created_at)` - 타임라인 최신순 정렬

## 3. 핵심 비즈니스 로직 (Business Logic)

### 3.1 연차 차감 산정 규칙
1.  **시각 입력**: 사용자가 선택한 시작/종료 시각의 분 단위를 계산합니다.
2.  **정책 단위 검증**: 입력된 시각이 시스템 설정 단위(예: 60분)의 경계값인지 확인합니다.
3.  **점심시간 제외**: 신청 구간이 점심시간(`lunch_start` ~ `lunch_end`)을 포함하는 경우 해당 시간을 차감 계산에서 제외합니다.
4.  **중복 체크**: 동일 사용자의 기존 신청 시간대와 겹치는지 검증합니다. 반려(`REJECTED`)된 건은 점유 시간에서 제외하여 재신청이 가능하도록 합니다.
5.  **한도 검증**: 당일 총 차감 시간이 8시간을 초과할 수 없습니다.

### 3.2 결재 상태 전이 (State Machine)
- **기본 흐름**: `PENDING` → `APPROVED` (또는 `REJECTED`)
- **충돌 방지**: 결재 처리 시점의 상태를 재검증하여, 이미 처리된 건에 대한 중복 결재를 원천 차단합니다.
- **특수 로직**: 
  - `PM` 역할 사용자: 
    - 신청 시 즉시 `APPROVED` 상태로 전이 (자동 승인)
    - **전사 결재 권한**: 소속 팀에 관계없이 모든 대기 건에 대한 결재 권한 보유
  - `TEAM_LEAD` 역할 사용자: 
    - 본인 팀원의 건에 대해서만 승인 권한 보유 (소속 회사가 달라도 동일 팀명이면 결재 가능)
    - 셀프 결재 금지

## 4. UI/UX 디자인 시스템 (Dense UI)

SHIM은 업무용 시스템 특유의 높은 정보 밀도를 수용하기 위해 **Dense UI** 디자인 시스템을 채택했습니다.

- **디자인 토큰**: `src/static/css/app.css` 내에 정의된 색상 및 간격 변수를 사용합니다.
- **레이아웃**: `base.html`을 기반으로 사이드바와 메인 컨텐츠 영역이 고정된 Shell 구조를 가집니다.
- **가독성**: 좁은 간격에서도 텍스트 가시성을 확보하기 위해 전용 음영(Muted) 및 대비(Border) 토큰을 적용했습니다. 
- **컴포넌트 통합**: 팀 캘린더와 같은 복합 화면은 필터와 본문을 단일 패널로 통합하여 시각적 인지 부하를 줄였습니다.

## 5. 배포 및 운영 전략

### 5.1 Docker 운영
- `infra/docker/Dockerfile`: Python Slim 이미지를 기반으로 멀티스테이지 빌드는 아니지만 최적화된 레이어를 구성합니다.
- 환경 변수 `SHIM_SECRET_KEY`가 주입되지 않을 경우 보안 경고와 함께 기본값으로 기동되나, 운영 시에는 반드시 `.env` 주입이 권장됩니다.

### 5.2 포터블(Portable) 운영
- PyInstaller를 사용하여 Python 런타임을 포함한 단일 바이너리를 생성합니다.
- 데이터베이스 및 로그 파일은 실행 파일 주변의 `data/` 디렉터리에 격리 저장됩니다.

- `v1.3.2`: **PM 자동 승인 및 UI 최적화**. PM 역할 사용자 신청 시 즉시 승인 로직 반영. 사용자 대시보드 상단 통계 요약 카드 추가. 팀 캘린더 조회 필터 상단 패널 분리.
- `v1.3.1`: **엔진/의존성(Tailwind v4)** 업데이트. 결재 가능 역할 확장(PM), 대시보드 메뉴 분리(결재·팀 캘린더·히스토리), 반려 건 시간 점유 해제 로직 보정.
