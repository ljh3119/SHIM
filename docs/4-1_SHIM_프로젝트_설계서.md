# SHIM 시스템 상세 설계서 (Technical Specification)

**애플리케이션 버전**: 1.5.14  
**최종 업데이트**: 2026-05-29  
**문서 성격**: 시스템 아키텍처, 데이터 모델 및 비즈니스 규칙에 대한 기술적 표준 정의

---

## 0. 설계 철학 및 시스템 정체성 (Design Philosophy & Identity)

SHIM은 대규모 인사 관리 시스템(ERP)을 지향하지 않습니다. 본 시스템의 존재 목적은 다음과 같은 특수 환경에서의 **'협업 가시성 확보'**에 집중합니다.

### 0.1 핵심 정체성
- **협업 가시성 도구 (Visibility Tool)**: "누가 휴가인가"를 넘어 "현재 프로젝트 가용 인력이 누구인가"를 팀 단위로 공유하는 가벼운 대시보드입니다.
- **현장 특화형 (Field-Oriented)**: 1~3년 단위의 단기 프로젝트, 여러 회사가 컨소시엄으로 참여하는 환경, 외부망이 차단된 폐쇄망 현장에 최적화되어 있습니다.
- **초경량성 (Zero-Configuration)**: 별도의 DB 서버나 런타임 설치 없이 폴더 복사만으로 즉시 가동되는 포터블 환경을 지향합니다.

### 0.2 개발 및 확장 한계선 (Boundaries)
시스템의 복잡도를 낮추고 유지보수성을 높이기 위해 다음의 선을 유지합니다.
- **포함 범위 (In-Scope)**: 캘린더 가독성 개선, 현장 중심의 상태 정보(출장/공가/기타 부재 등) 확장, 프로젝트 기간 내 통계 리포트, 다수 회사 통합 팀 관리, 관리자 전용 정정 기능.
- **제외 범위 (Out-of-Scope)**: 급여 산정 및 노무 정산 로직, 인사 고과 관리, 외부 메신저/메일 서버와의 복잡한 연동, 무거운 RDBMS로의 전환.

## 1. 아키텍처 개요 (Architecture Overview)

SHIM은 폐쇄망 환경의 제약 조건을 극복하면서도 사용자에게 현대적인 웹 경험을 제공하도록 설계되었습니다.

- **Monolithic 구조**: FastAPI를 중심으로 정적 자산, 템플릿, 비즈니스 로직, 데이터 접근 계층을 단일 프로세스에서 처리합니다.
- **Lifespan 라이프사이클 관리**: FastAPI의 최신 `lifespan` 컨텍스트 매니저를 도입하여 애플리케이션 시작 시 데이터베이스 스키마 마이그레이션 및 공휴일 시딩을 자동 수행하고, 종료 시점에 `database.engine.dispose()`를 명시적으로 호출해 SQLite 커넥션 풀을 안전하게 정리하고 락 파일 프리징을 원천 차단합니다.
- **동기식 라우팅 구조 (Synchronous Routing)**: 동기식 SQLAlchemy DB 커넥션을 호출할 때 메인 이벤트 루프가 블로킹되는 현상을 방지하기 위해 모든 FastAPI 라우터는 동기식(`def`)으로 작성됩니다. FastAPI는 동기식 라우터를 내부 스레드풀에서 안전하게 병렬 처리합니다.
- **데이터 저장소**: 별도의 DBMS 설치가 필요 없는 SQLite를 사용하며, 동시성 향상을 위해 WAL(Write-Ahead Logging) 모드를 사용합니다.
- **보안 모델**: JWT 기반의 상태 비저장(Stateless) 인증을 수행하며, 토큰은 HttpOnly 쿠키에 저장되어 XSS 공격을 방지합니다.

## 2. 데이터 모델 (Data Schema)

### 2.1 핵심 엔티티
- **Users**: 조직원 정보 및 잔여 연차 관리. `role` 필드를 통한 RBAC 제어.
- **Leaves**: 연차 신청 기록. 신청 시점의 정책 스냅샷(`snapshot_*`) 보관.
- **UserYearlyLeaveAllocations**: 연도별 사원 연차 할당 독립 관리. 연도/사원 단위로 격리된 연차 총량을 기록.
- **AuditLogs**: 관리자 행위 및 시스템 설정 변경 이력 추적.
- **SystemSettings**: 전사 승인 정책, 시간 단위, 업무 시간 범위 등 전역 설정.

### 2.2 인덱스 설계 (Performance)
조회 성능 최적화를 위해 다음 복합 인덱스를 적용합니다.
- `idx_leaves_user_date`: `(user_id, date)` - 개인별 사용 현황 조회
- `idx_leaves_year_date`: `(year, date)` - 전사 연도별 캘린더 조회
- `idx_leaves_created`: `(created_at)` - 타임라인 최신순 정렬
- `ix_leaves_status_is_deductive`: `(status, is_deductive)` - 결재 상태 및 차감 여부 기반 통계 필터링

## 3. 핵심 비즈니스 로직 (Business Logic)

### 3.1 연차 차감 산정 규칙
1.  **시각 입력 및 생략 처리**:
    - 일반 신청 시: 사용자가 선택한 시작/종료 시각의 분 단위를 계산합니다.
    - 시간 생략(다수일 신청 또는 단일 하루종일 체크박스 활성화) 시: 백엔드로 빈 시간값(`""`)이 전달되며, 서버는 시스템 설정에 정의된 기본 근무 시작 시각(`work_start_minute`)과 종료 시각(`work_end_minute`)을 분 단위에서 `"HH:MM"` 문자열로 자동 변환(예: 540 -> `09:00`, 1080 -> `18:00`)하여 주입합니다.
2.  **정책 단위 검증**: 입력된 시각이 시스템 설정 단위(예: 60분)의 경계값인지 확인합니다. (시간을 생략한 자동 하루 종일 신청 시에는 해당 시스템 기본 시각 자체가 유효한 정책 경계에 속하므로 통과 처리됩니다.)
3.  **점심시간 제외**: 신청 구간이 점심시간(`lunch_start` ~ `lunch_end`)을 포함하는 경우 해당 시간을 차감 계산에서 제외합니다.
4.  **중복 체크**: 동일 사용자의 기존 신청 시간대와 겹치는지 검증합니다. 반려(`REJECTED`)된 건은 점유 시간에서 제외하여 재신청이 가능하도록 합니다.
5.  **한도 검증**: 당일 총 차감 시간이 8시간을 초과할 수 없습니다.
6.  **차감 여부 구분**: 신청 시 '연차 차감' 여부를 선택할 수 있습니다. '공가/출장' 등 차감 안 함 선택 시 사용자의 잔여 연차 계산에서 제외되며, 대신 증빙을 위한 '사유' 입력을 필수로 합니다.

### 3.2 결재 상태 전이 (State Machine)
- **기본 흐름**: `PENDING` → `APPROVED` (또는 `REJECTED`)
- **충돌 방지**: 결재 처리 시점의 상태를 재검증하여, 이미 처리된 건에 대한 중복 결재를 원천 차단합니다.
- **특수 로직**: 
  - `PM` 역할 사용자: 
    - 신청 시 즉시 `APPROVED` 상태로 전이 (자동 승인)
    - **전사 결재 권한**: 소속 팀에 관계없이 모든 대기 건에 대한 결재 권한 보유
  - `TEAM_LEAD` 역할 사용자: 
    - 본인 팀원의 건에 대해서만 승인 권한 보유 (소속 회사가 달라도 동일 팀명이면 결재 가능)
    - 셀프 결재 금지

### 3.3 캘린더 공유 및 조회 범위 정책 (Calendar Visibility Policy)
일반 사원(`STAFF`) 및 팀장(`TEAM_LEAD`)에게 제공되는 팀 캘린더 화면의 사원 목록 및 연차 현황 조회 범위는 시스템 마스터 설정에 정의된 3가지 공유 수준에 따라 격리 또는 확장됩니다.

1. **공유 안 함 (none)**: 
   - `team_calendar_visible = False`, `company_calendar_visible = False`
   - 사원은 자신의 휴가 일정만 조회할 수 있습니다. 
   - 일반 사원 및 팀장의 사이드바에서 "팀 캘린더" 메뉴가 감춰지며, 직접 URL 접근 시 대시보드로 리다이렉트 처리됩니다.
2. **소속 팀원 공유 (team)**:
   - `team_calendar_visible = True`, `company_calendar_visible = False`
   - 사원 및 팀장은 본인과 동일한 팀(`team` 컬럼 명칭 일치 기준) 내 사원의 휴가 현황만 조회할 수 있습니다.
3. **전사 공유 (company)**:
   - `team_calendar_visible = True`, `company_calendar_visible = True`
   - 사원 및 팀장도 부서/팀의 격리 없이 전사 모든 사원의 휴가 현황을 PM과 동일하게 열람할 수 있습니다.
4. **동적 사이드바 라벨링 및 제목 매핑**:
   - 전사 공유 활성화(`company_calendar_visible = True` 또는 PM 역할) 상태 시 유저 사이드바의 링크 라벨과 캘린더 화면 상단 제목이 '프로젝트 캘린더'로 자동 변경 표출되며, 설명문 역시 '프로젝트의 연차 현황입니다'로 정밀 조율됩니다. 그 외의 격리 상태인 경우에는 '팀 캘린더' 및 '{팀명} 캘린더' / '{팀명}팀의 연차 현황입니다'로 출력됩니다.

*참고: `PM` 및 `ADMIN` 권한 사용자는 설정값에 영향을 받지 않고 상시 전사 캘린더 조회 권한을 보장받습니다.*

### 3.4 다수일 일괄 신청 (Bulk Leave Request)
1. **입력 분할 및 다중 처리**: 사용자 대시보드 직접 신청 패널(기간 선택) 또는 캘린더 다중 선택 모드를 통해 쉼표(`,`)로 구분된 날짜 목록(예: `2026-06-08,2026-06-09`)을 `POST /user/leave` API에 전달합니다.
2. **트랜잭션 원자성 (Atomicity)**: 데이터베이스 커밋 전에 하나의 단일 세션 트랜잭션 블록 내에서 신청을 일괄 처리합니다. 날짜별 신청 검증 중 단 하나라도 정책 위반(중복 시간, 연차 잔여 시간 초과 등)이 발생할 경우, 전체 신청 데이터를 롤백하여 일부 신청만 승인되는 정합성 불일치를 원천 차단합니다.
3. **주말/공휴일 자동 제외**: 입력된 날짜 리스트 중에서 주말(토, 일) 및 공휴일(대한민국 관공서 공휴일 정책 데이터베이스 조회 기준)에 해당하는 날짜는 신청 대상에서 자동으로 스킵 처리합니다.
4. **통합 감사 로그 (Audit Logs)**: 여러 날짜에 대해 연차가 일괄 등록될 때, 사원 정보와 신청 날짜 리스트, 그리고 총 신청 건수 등의 세부 정보를 단일 감사 로그 레코드(`APPLY_LEAVE_BULK` 액션)로 병합 기록하여 감사 로그 테이블의 가독성과 성능을 높입니다.

### 3.5 시간 생략 및 자동 하루종일(Full-day) 정책 (Time Omission & Auto Full-Day Policy)
1. **시간 생략 연차 신청**: 사용자가 연차 신청 시 시간을 직접 지정하지 않아도 되도록 지원합니다. 이는 다수일 신청이나 단일 하루종일 연차 신청 시 불필요한 입력을 방지하기 위함입니다.
2. **백엔드 매핑 로직**: `POST /user/leave` API의 `start_time` 및 `end_time` 매개변수는 기본값으로 빈 문자열(`""`)을 허용합니다. 만약 빈 값이 수신되면 시스템 설정(`SystemSettings`)에서 업무 시작 분(`work_start_minute`)과 업무 종료 분(`work_end_minute`)을 가져와 `"HH:MM"` 문자열로 포맷팅하여 스냅샷 빌더에 전달합니다. 이로써 점심시간을 제외하고 하루 8시간 부재로 정확히 산정됩니다.
3. **프론트엔드 제어 (UX)**:
   - **단일 날짜**: '하루 종일' 체크박스를 제공하여, 선택 시 시간 선택 UI를 감추고 폼 제출 시 시간 값을 빈 문자열로 백엔드에 전달합니다.
   - **기간/다수일 신청**: 다수일 신청 및 캘린더 다중 선택 시에는 시간 지정의 모호성을 제거하기 위해 시간 입력란을 UI에서 원천 숨기고 하루종일 신청으로만 접수되도록 강제합니다. (선택 날짜가 1일이어도 모드 기준을 적용합니다.)
   - **비차감 신청**: 공가/출장 등 비차감 신청 시에도 동일한 룰을 적용하여 하루종일로 일괄 등록합니다.

### 3.6 비밀번호 관리 및 감사 로그 보안/한글화 정책 (Password & Audit Log Policies)
1. **비밀번호 자가 변경 및 검증**:
   - 일반 사원 및 관리자는 개인정보 수정 모달을 통해 자가 비밀번호를 직접 변경할 수 있습니다.
   - 보안 강화를 위해 새 비밀번호는 **최소 4자 이상**의 강제적인 유효성 검사 규칙을 적용받습니다.
   - 입력 오류를 방지하도록 프론트엔드 변경 모달은 **3개 필드**(현재 비밀번호, 새 비밀번호, 새 비밀번호 확인) 입력을 강제하고 상호 대조 검증을 수행합니다.
2. **비밀번호 로깅 마스킹 (Security)**:
   - 비밀번호 변경에 따라 적재되는 감사 로그(`CHANGE_PASSWORD`, `CHANGE_ADMIN_PASSWORD`)는 데이터 보안성을 위해 이전 값(`old_data`)과 신규 값(`new_data`)을 데이터베이스 저장 및 조회 시 `"*****"`로 안전하게 마스킹 처리하여 보존합니다.
3. **감사 로그 한글화 (Localization)**:
   - 데이터베이스에 영문 텍스트 형태로 적재된 감사 로그 액션 명칭(`action`) 및 대상 정보(`target`) 데이터는 관리자 화면에서 출력되거나 엑셀 다운로드될 때 가독성을 극대화하기 위해 공용 번역 헬퍼 함수(`get_audit_action_label`, `get_audit_target_label`)를 통해 자연스러운 한국어로 변환됩니다.
   - 이 헬퍼 함수는 일반적인 사원/관리자/공휴일 개별 식별자뿐만 아니라, `APPLY_LEAVE_BULK` 처리 시 전달되는 일괄 신청 범위(`Scope`, `Year`, `Count` 파라미터 조합)까지 일관되게 한글로 구조화하여 파싱합니다.

### 3.7 일반 사용자 연차 신청 직접 취소 정책 (User-Initiated Request Cancellation)
1. **취소 권한 및 대상 범위**:
   - 일반 사원은 본인이 직접 기안(신청)한 연차에 한하여 취소를 수행할 수 있습니다.
   - 단, 이미 승인/반려/취소 처리가 완전히 끝난 건은 제외되며 오직 **결재 대기(PENDING)** 상태인 휴가 신청 건에 대해서만 취소가 가능하도록 제한적 쓰기 권한이 부여됩니다.
2. **트랜잭션 및 상태 전이**:
   - 취소 요청 발생 시 비즈니스 유효성(보안 소유자 일치 여부 및 결재 대기 상태 여부)을 검증한 뒤, 해당 연차의 상태를 `CANCELED`로 안전하게 전이시킵니다.
   - 트랜잭션 도중 오류 발생 시 `db.rollback()`이 보장되도록 예외 처리를 연동했습니다.
3. **감사 추적 및 로깅**:
   - 연차 취소 시 `AuditLogs` 테이블 내 `actor_id`에는 로그인된 사원의 ID가 기록되며, 취소된 연차의 날짜와 차감 시간 범위 등이 감사 로그 내용으로 안전하게 기록됩니다.

## 4. UI/UX 디자인 시스템 (Dense UI)

SHIM은 업무용 시스템 특유의 높은 정보 밀도를 수용하기 위해 **Dense UI** 디자인 시스템을 채택했습니다.

- **디자인 토큰**: `src/static/css/app.css` 내에 정의된 색상 및 간격 변수를 사용합니다.
- **레이아웃**: `base.html`을 기반으로 사이드바와 메인 컨텐츠 영역이 고정된 Shell 구조를 가집니다.
- **가독성**: 좁은 간격에서도 텍스트 가시성을 확보하기 위해 전용 음영(Muted) 및 대비(Border) 토큰을 적용했습니다. 
- **컴포넌트 통합**: 팀 캘린더와 같은 복합 화면은 필터와 본문을 단일 패널로 통합하여 시각적 인지 부하를 줄였습니다.
- **동적 HSL 해시 기반 회사/팀 배지**: 
  - 다중 회사 및 다중 팀 식별을 위해 HSL 기반의 색상 배지를 동적 렌더링합니다.
  - 모양 및 색상 속성을 이원화하여 사용자가 더 중요하게 봐야 하는 **팀(Team)**은 높은 채도(`75%`), 어두운 텍스트(`15%`), 파랑/보라 계열 색조(`180~340도`) 및 둥근 캡슐(`rounded-full`) 모양으로 시인성을 극대화했고, 보조 정보인 **회사(Company)**는 부드러운 파스텔 톤(`20~180도`)과 각진 둥근 모양(`rounded`)으로 은은하게 낮추어 시각적 계층(Team-First)을 확립했습니다.
  - 해싱 전 `"company:"`, `"team:"` 접두어(Salt)를 결합하여 우연한 색상 충돌을 원천 방지합니다.
- **캘린더 테이블 너비 최적화**: 
  - 어드민 캘린더 및 팀 캘린더에서 가로 폭을 확보하기 위해 사원명은 이름만 표시(`(사원ID)` 제거)하고 비활성 텍스트 배지도 제거(반투명으로만 표현)하여 사원명 열 너비를 **`4.25rem`**으로 축소했습니다.
  - 이로써 세이브된 공간을 활용해 회사/팀 컬럼 너비를 **`5.5rem ~ 7rem`**으로 확장하여, "사립유치원회계" 등 최대 7자 팀명도 줄바꿈 없이 한 줄로 깔끔하게 렌더링되도록 밀도를 극대화했습니다.

## 5. 배포 및 운영 전략

### 5.1 Docker 운영
- `infra/docker/Dockerfile`: Python Slim 이미지를 기반으로 멀티스테이지 빌드는 아니지만 최적화된 레이어를 구성합니다.
- 환경 변수 `SHIM_SECRET_KEY`가 주입되지 않을 경우 보안 경고와 함께 기본값으로 기동되나, 운영 시에는 반드시 `.env` 주입이 권장됩니다.

### 5.2 포터블(Portable) 운영
- PyInstaller를 사용하여 Python 런타임을 포함한 단일 바이너리를 생성합니다.
- 데이터베이스 및 로그 파일은 실행 파일 주변의 `data/` 디렉터리에 격리 저장됩니다.
- **백그라운드 서버 기동 및 데몬화**: 포터블 런처(`SHIM_Portable.exe`) 실행 시, 기본 포트(8000)의 사용 여부를 자동으로 탐색하여 비어있는 포트로 즉시 할당하고, 터미널 창을 닫아도 서버가 백그라운드에서 동작하도록 자가 포크(`subprocess.Popen` + `CREATE_NO_WINDOW`) 기동합니다.
- **Mutex 기반 중복 실행 방지**: 실행 파일 경로의 MD5 해시를 기반으로 전역 뮤텍스(`Global\SHIM_Portable_Mutex_<Hash>`)를 선점하여, 동일 디렉터리에서의 중복 기동을 물리적으로 차단합니다. 중복 기동 감지 시 기존 트레이에 벌룬 알림을 전송하고 새 프로세스는 즉시 종료됩니다.
- **웹 브라우저 자동 오픈 배제**: Docker 및 포터블 환경의 경량 기동 철학에 부합하도록 기동 시 브라우저 자동 팝업 로직은 완전히 배제했습니다. 브라우저 접속은 트레이 아이콘을 통한 수동 오픈 또는 수동 접속 주소 입력을 통해 수행합니다.
- **윈도우 네이티브 시스템 트레이 아이콘 (Systray) 연동**: 백그라운드 기동과 동시에 시스템 트레이 영역에 프로젝트 로고 아이콘이 올라갑니다. 더블 클릭 또는 우클릭 메뉴의 'SHIM 브라우저 열기'를 선택하여 실행 포트(`http://localhost:{port}`)로 브라우저를 즉시 호출할 수 있고, '종료' 선택 시 백그라운드 프로세스가 트레이 자원을 반환하며 완전히 안전하게 종료됩니다.

## 6. 성능 최적화 및 아키텍처 설계 (Performance & Architecture Design)

### 6.1 SystemSettings 실시간 직접 조회 및 캐시 제거 (Direct DB Query & Cache Removal)
1. **문제 정의**: 다중 Uvicorn 워커 구동 환경에서 인메모리 캐시 불일치로 인해 연차 계산 바운더리 오류 등 상태 불일치 버그가 유발될 위험이 있었습니다.
2. **아키텍처 단순화**: 캐싱 메커니즘을 전면 제거하고, 전사 설정 조회 시 항상 데이터베이스(`SystemSettings` 테이블)를 직접 조회하도록 단순화하여 데이터 실시간 일관성을 원천적으로 보장합니다.
3. **성능 및 신뢰성**: 동기식 라우터와 커넥션 풀을 기반으로 동작하여 직접적인 SQLite I/O가 시스템 전반의 신뢰성에 영향을 미치지 않도록 구조를 극단적으로 단순화했습니다.

### 6.2 관리자 캘린더 N+1 쿼리 최적화 (N+1 Query Resolution)
1. **문제 정의**: 관리자 연차 캘린더(`/admin/leaves/calendar`) 조회 시 사원 목록(N명)을 순회하며 각 사원마다 루프 내에서 개별 `Leaves` 테이블 조회를 실행하여 N+1 데이터베이스 쿼리가 발생하였습니다. 사원 수가 늘어남에 따라 렌더링 성능이 기하급수적으로 저하되는 병목이었습니다.
2. **Bulk 쿼리 리팩토링**: 루프 내 쿼리를 완전히 제거하고, 조회 대상 사원 ID 목록(`user_ids`)을 먼저 추출한 뒤 `user_id.in_(user_ids)` 조건과 해당 연월 범위 조건을 조합하여 `Leaves` 테이블을 단 1회의 SQL 쿼리로 일괄 조회(Bulk Query)합니다.
3. **메모리 맵핑 매칭**: 조회된 Bulk 결과를 `{user_id: [leaves, ...]}` 형태의 딕셔너리로 사전 맵핑하고, 사원 루프 내에서는 이 딕셔너리를 O(1)로 조회하여 매칭함으로써 데이터베이스 쿼리 횟수를 사원 수에 무관하게 단 1회로 고정하여 성능을 극대화하였습니다.

### 6.3 캘린더 미결재 연차 렌더링 및 스타일링 (Pending Leave Visualization)
1. **문제 정의**: 관리자 연차 캘린더 및 팀 캘린더에서 승인 완료된 연차와 승인 대기(미결재) 상태인 연차가 시각적으로 명확히 구별되지 않아 운영 혼선이 생길 가능성이 높았습니다.
2. **해결 방안**: 날짜별 연차 목록 중 승인 대기(`PENDING`)인 신청 건이 존재하는 경우 해당 날짜 블록(또는 연차 정보 카드)에 `pending` 스타일 클래스를 동적으로 주입합니다.
3. **시각 효과 구현**: `.pending` 스타일 규칙은 시각적으로 불필요한 노이즈를 유발하던 점선 테두리를 완전히 제거(`border: none !important;`)하고, 부드러운 투명도 조정(`opacity: 0.55`) 및 그레이스케일(`filter: grayscale(0.35)`) 효과의 조화를 통해 미결재(대기) 상태임을 은은하게 강조하도록 구성했습니다. 공가/출장(보라색) 및 일반 연차(빨간색/주황색) 등 각 유형별 배경색 정체성은 유지하면서 대기 상태를 오버레이하여 시각적 직관성을 향상했습니다.

### 6.4 자체 DDL 자동 마이그레이션 엔진 (Custom DDL Auto-Migration Engine)
1. **설계 배경**: PyInstaller 포터블 EXE 패키징 환경이나 단독 구동 시 Alembic과 같은 외부 마이그레이션 도구는 경로 설정 및 실행 프로세스의 비대화로 적합하지 않습니다.
2. **자가 복구 메커니즘**: 애플리케이션 기동 시점(Startup)에 SQLAlchemy의 `create_all`을 통해 기본 테이블 스키마가 없는 경우 생성하며, 이후 `schema_versions` 테이블을 통해 마이그레이션 기록을 조회합니다.
3. **PRAGMA를 통한 정합성 검사**: 순차적이고 버전화된 DDL 마이그레이션 스크립트를 정의하고, 각 실행 전에 `PRAGMA table_info(테이블명)` 조회를 통해 신규 추가될 컬럼의 존재 여부를 미리 검사함으로써, 수동으로 수정된 데이터베이스에 대해서도 중복 컬럼 추가 오류(`duplicate column`) 없이 안전하게 ALTER TABLE을 실행합니다.
4. **정식 버전 출시(운영망 배포) 시 베이스라인(Baseline) 정책**:
   - **개발/테스트용 임시 마이그레이션 구분**: 정식 배포 전까지 개발 중에 발생하는 임시 컬럼 추가 이력(예: `v1.4.0`, `v1.5.0`, `v1.5.6` 등)은 '개발 단계 스키마 변경 사항'에 속합니다.
   - **스키마 통합(Squash)**: 외부에 공개되어 실제 상용 서비스(Production)가 시작되는 최초 정식 버전을 빌드하는 시점에는 이전의 모든 파편화된 마이그레이션 스텝을 SQLAlchemy 기본 스키마(`models.Base.metadata.create_all`)로 완전히 병합(Squash)하여 베이스라인으로 승격합니다.
   - **운영망 마이그레이션 분리**: 정식 출시 버전 이후부터 발생하는 실운영 상태의 변경 건만 `migrations.py`에 공식 버전 단위의 신규 스케일 마이그레이션으로 등록해 나감으로써 데이터베이스 설계의 복잡성을 통제합니다.

### 6.5 제로 컨피그 포트 및 보안 키 자동화 (Zero-Config Port & Secret Key Automation)
1. **포트 자동 감지 및 할당**: `SHIM_Portable.exe` 및 `shim_portable.py` 실행 시 설정된 기본 포트(8000)를 먼저 탐색한 후, 사용 중일 경우 다음 포트로 자동 시프트하여 바인딩을 시도합니다. 이미 해당 포트에서 `SHIM_Portable.exe`가 실행 중이라면 새 창을 여는 대신 브라우저만 리다이렉트합니다.
2. **비밀키 무인 자동 생성**: Stateless JWT 인증용 `SHIM_SECRET_KEY`를 별도로 주입하지 않은 경우, `data/secret.key` 경로를 조회하여 기존 저장된 키가 없다면 cryptographically secure한 64글자 랜덤 비밀키를 자동으로 무인 생성하고 파일로 영구 저장해 초기 배포 허들을 완전히 제거합니다.

### 6.6 연도별 연차 독립 및 연말/연초 권고 알림 배너 (Yearly Leave Isolation & Smart Notification)
1. **연도별 연차 관리 독립화**:
   - 기존에는 특정 사용자의 특정 연도 연차를 개별 수정/일괄 지급할 때 사원의 기본 정보 필드(`Users.total_leave_hours`)를 강제로 동기화하여 변경하는 로직이 포함되어 있었습니다. 이는 다른 연도의 연차 잔여량 계산 시 기본값 참조 과정에서 부작용(다른 연도의 연차 한도가 원치 않게 연쇄 덮어쓰기되는 버그)을 유발했습니다.
   - 이를 극복하기 위해 `api_admin.py` 내의 `update_user_leave_days` 및 `bulk_update_user_leave_days` 엔드포인트에서 `Users.total_leave_hours = new_hours`와 같이 기본 프로필 한도를 덮어쓰는 코드를 전면 배제했습니다. 이로써 사원의 과거/현재/미래 연차 정보는 데이터베이스 `UserYearlyLeaveAllocations` 내에서 연도 단위로 완벽하게 물리적 및 논리적 격리를 유지하게 됩니다.
2. **연말/연초 대시보드 권고 배너 및 스마트 자동 숨김 정책**:
   - 매년 **12월 말 ~ 1월 초(12월, 1월)** 사이에 관리자가 대시보드(`/admin/dashboard`)에 진입할 경우, 새해 연차 지급 작업을 유도하는 안내 배너가 자동으로 활성화됩니다.
   - 단, 이미 새해 연차 설정이 끝났음에도 고정된 기간 동안 계속 배너가 떠 있어 관리자에게 시각적 피로감을 유발하는 것을 방지하기 위해 **스마트 자동 숨김** 정책을 내장했습니다.
   - `UserYearlyLeaveAllocations` 테이블을 조회하여 내년도(`next_year` = 12월 기준 차년도, 1월 기준 당해 연도)에 해당하는 연차 할당 레코드가 시스템 상에 **최소 1건 이상** 존재할 경우, 이미 연차 일괄 지급이 완료된 것으로 판단하여 배너 플래그(`show_year_end_notice`)를 자동으로 `False` 처리합니다.

### 6.7 네이티브 윈도우 시스템 트레이 및 Graceful Shutdown (Systray & Graceful Shutdown)
1. **표준 ctypes 기반 경량화 구현**: 외부 라이브러리(Pillow, PySide, PyQt 등)에 의존하지 않고, Windows `ctypes` 표준 라이브러리만을 활용해 Win32 API를 직접 바인딩하여 50MB 이하의 포터블 바이너리 사양을 준수했습니다.
2. **마스터-워커 다중 프로세스 기동 구조**:
   - `SHIM_Portable.exe`가 `--server` 인수로 백그라운드 포크될 때, 직접 Uvicorn 웹 엔진을 탑재하지 않고 마스터 프로세스 역할을 수행합니다.
   - 마스터 프로세스는 내부적으로 `subprocess.Popen`을 사용해 자기 자신을 `--uvicorn-worker` 인자 및 포트와 함께 Uvicorn 전용 자식 프로세스로 분리 기동(`CREATE_NEW_PROCESS_GROUP` 적용)시킵니다.
   - 이로써 Uvicorn 웹 엔진과 트레이 전용 Win32 메시지 루프가 프로세스 수준으로 완벽하게 격리되어, Uvicorn 서버 오동작 시에도 트레이 프로세스가 생명주기를 안전하게 통제할 수 있습니다.
3. **트레이 메시지 펌프 및 메뉴 인터랙션**:
   - `NIM_ADD`를 통해 시스템 트레이 영역에 전용 아이콘과 포트 상태 툴팁, 벌룬 팁 알림을 등록합니다.
   - 트레이 아이콘에 마우스 우클릭을 감지하면 `TrackPopupMenu`를 사용하여 컨텍스트 메뉴(SHIM 브라우저 열기, 종료)를 호출하며, 메뉴 바깥 영역 클릭 시 메뉴 창이 닫히지 않는 윈도우 네이티브 트랙 버그를 `SetForegroundWindow` 호출 순서 정정 및 `PostMessageW(hwnd, WM_NULL, ...)` 처리를 통해 극복했습니다.
4. **시그널 전송을 통한 Graceful Shutdown**:
   - 트레이 메뉴에서 '종료'를 누르면, 즉시 시스템 벌룬 알림으로 `"SHIM 서버가 안전하게 종료되었습니다."` 팝업을 노출하고, 콘솔에 `[알림] 시스템을 안전하게 종료합니다...` 메시지 출력 후 `time.sleep(1.5)` 대기합니다.
   - 이후, Uvicorn 자식 프로세스 그룹에 `signal.CTRL_BREAK_EVENT` 안전 종료 시그널을 전달하여 FastAPI의 `lifespan` shutdown 훅(`engine.dispose()`)을 완벽하게 실행하고 자식 프로세스가 정상 종료되는 것을 대기합니다.
   - 마지막으로 트레이 알림 자원(`NIM_DELETE`)을 완벽히 소거하고 마스터 프로세스를 종료함으로써, SQLite DB 락 파일이 완전히 병합 및 해제된 안전한 종료를 보장합니다.

### 6.8 윈도우 중복 실행 제어 (Mutex Execution Guard)
1. **문제 정의**: 사용자가 런처를 더블클릭할 때 마우스 미세 진동이나 중복 클릭으로 인해 여러 백그라운드 프로세스가 동시에 기동되어 포트 충돌 및 로컬 시스템 자원을 낭비하는 문제를 방어합니다.
2. **경로별 전역 뮤텍스(Mutex) 선점**:
   - Windows `kernel32.CreateMutexW` API를 활용하여 전역 뮤텍스를 생성합니다.
   - 단, 로컬 PC에서 여러 개의 독립된 SHIM 환경을 독립적으로 띄울 수 있도록 실행 파일 디렉토리 절대경로를 MD5 해싱하여 고유 명칭(`Global\SHIM_Portable_Mutex_<Hash>`)으로 채택했습니다. 이로써 동일 디렉토리 내에서의 이중 기동만 정밀 통제합니다.
3. **자식 프로세스 검증 우회**: 마스터가 self-fork하는 자식 Uvicorn 프로세스(`--uvicorn-worker`)가 기동될 때는 뮤텍스 중복 체크를 우회(Pass)하도록 예외 제어 처리를 구현하여 프로세스 부팅 오류를 차단했습니다.
4. **기존 트레이 알림 연동 및 소멸**: 중복 기동이 감지되면 `user32.FindWindowW`를 통해 기존 백그라운드 마스터 트레이 윈도우(`SHIMTrayClass`)를 검색하고, 존재하면 `PostMessageW`로 벌룬 알림 이벤트(`ID_TRAY_TRIGGER_BALLOON` / `WM_COMMAND`)를 전달한 뒤 자신은 `sys.exit(0)`으로 즉각 조용히 종료됩니다. 수신받은 기존 트레이 마스터는 사용자에게 벌룬 팝업 알림을 송신합니다.

### 6.9 엑셀 대용량 최적화 및 스트리밍 (Excel Export Memory Optimization)
1. **문제 정의**: 관리자가 대용량 연차 타임라인이나 신청 이력을 엑셀 파일로 출력할 때 `openpyxl`은 모든 셀 데이터를 메모리 상의 DOM 객체로 생성하므로, 데이터가 수만 건으로 누적될 경우 피크 메모리가 수백 MB 이상 급격히 치솟아 저사양 로컬 구동 PC가 정지될 위험이 있었습니다.
2. **WriteOnlyWorkbook 스트리밍 전환**: `openpyxl`의 기존 인메모리 DOM 생성 형식을 배제하고 `Workbook(write_only=True)` 방식을 적용하여, 한 행씩 `append`할 때마다 데이터가 메모리에 적재되지 않고 디스크 파일 스트림으로 실시간 기록되도록 설계했습니다.
3. **순차 다중 시트 렌더링**: 스트리밍 파일 쓰기 제약에 따라 복수의 시트를 동시에 다루지 않고, 첫 번째 시트("연차 현황 요약")를 생성 및 데이터 작성을 완료한 뒤에 이어서 두 번째 시트("상세 신청 내역")를 작성하는 순차 데이터 파이프라인 방식으로 빌더 구조를 리팩토링하여 피크 메모리를 10MB 고정 상수로 축소하는 데 성공했습니다.

### 6.10 기동 시 데이터베이스 무결성 검증 (Database Self-Diagnostics)
1. **문제 정의**: 비정상적인 종료나 갑작스러운 전원 차단으로 인해 SQLite 데이터베이스 파일이 물리적으로 손상되는 정합성 문제를 방지할 안전망이 필요했습니다.
2. **자가 진단 파이프라인**: 애플리케이션 시작점(`startup_event()`) 첫머리에서 `PRAGMA quick_check;`를 실행하여 물리적 손상 여부를 검증합니다. 이 검사는 테이블 데이터 페이지와 인덱스의 물리 구조를 고속 스캔하므로 대용량 DB 환경에서도 기동 지연을 일으키지 않습니다.
3. **위험 전파 차단 및 경고**: 무결성 검증 결과가 비정상(`ok`가 아님)인 것으로 감지되면, 실행 콘솔과 로그 시스템에 데이터 손상 경고(`[SHIM DATABASE CORRUPT WARNING]`)를 매우 강력하게 출력하여 관리자가 최근 자동 핫 백업본(`.bak`)을 활용하여 조치할 수 있도록 복구 절차를 알립니다.

### 6.11 AuditLogs 조회 인덱싱 최적화 (AuditLogs Query Optimization)
1. **문제 정의**: 300인 규모 컨소시엄에서 5년 장기 운용 시 시스템 설정 변경 및 사원 활동 이력을 추적하는 `AuditLogs` 테이블의 레코드가 수십만 건 누적됩니다. 인덱스가 없는 기존 상태에서는 관리자 감사 로그 화면에서 필터링 조회나 최근 로그 정렬 시 Table Full Scan이 유발되어 화면 로딩 병목이 예상되었습니다.
2. **대량 적재 최적화 인덱스 설계**: 데이터 조회의 핵심 키가 되는 행위자(`actor_id`), 생성 일시(`timestamp`), 행동 유형(`action`) 컬럼에 다중 인덱스(`Index`)를 정의했습니다. 감사 로그는 삽입(Insert)만 빈번하고 기존 데이터의 수정/삭제가 일어나지 않는 불변 데이터셋이므로 인덱싱 추가에 따른 쓰기 병목이 거의 없으며, 읽기 락 점유 시간을 단축해 동시 사용자 경합을 예방합니다.
3. **개발 단계 빌드 연동**: 아직 정식 상용 출시 이전 개발 단계이므로, 복잡한 임시 마이그레이션 DDL 스크립트를 중복 누적하지 않고 데이터 설계 원본인 `models.py`에 인덱스 정의를 직접 명시하여 신규 빌드 시 깨끗한 최종 데이터베이스에 일괄 반영되도록 일원화했습니다.

### 6.12 연차 신청 점심시간 경계 예외 구체화 및 실시간 1차 차단 (Lunch Overlap Validation & Instant Block)
1. **문제 정의**: 직원이 점심시간 범위(예: 12:00 ~ 13:00) 내에서만 연차를 지정하는 등, 실제 근무시간 차감량이 0시간이 되는 부적절한 구간 입력을 신청 시 결재 반려 오버헤드나 비즈니스 예외를 초래했습니다.
2. **백엔드 예외 구체화**: 연차 신청 구간이 점심시간 범위 내에 완전히 속해 실질 차감 시간이 0 이하가 되는 케이스를 감지하여, 단순 500 에러나 모호한 문구 대신 선택 구간과 점심시간의 hh:mm 범위를 구체적으로 명시하는 세분화된 에러 메시지를 발생시킵니다.
3. **프론트엔드 실시간 입구컷 (Instant Block)**: 대시보드의 시간 입력 드롭다운 값이 바뀔 때마다 즉시 자바스크립트 유효성 평가(`onTimeSelectionChange()`)가 동작하여, 점심시간에 완전히 포함되는 비정상 선택 시 **직접 등록하기 버튼을 즉각 비활성화(`disabled`)하고 폼 하단에 적색 경고 라벨을 실시간 표출**해 직원의 잘못된 신청 시도 자체를 화면 단에서 선제적으로 1차 차단합니다.

### 6.13 사원 권한/상태 변경 시 세션 즉시 만료 (Session Invalidation on Role/Status Change)
1. **문제 정의**: 기존의 JWT 기반 인증 방식은 상태 비저장(Stateless)의 특성상 사원의 계정이 비활성화되거나 관리자 권한이 STAFF로 강등되더라도, 이미 발급된 JWT 토큰의 만료 전까지는 이전 권한으로 시스템을 계속 이용할 수 있는 보안 취약점이 있었습니다.
2. **토큰 버전 제어 시스템 (Token Versioning)**: 아직 정식 출시 전 개발 단계이므로 불필요한 임시 마이그레이션 DDL 스크립트는 누적하지 않고 생략하되, `models.py` 원본 모델 정의에 직접 컬럼을 명시하여 신규 설치 및 테스트 빌드 시 단번에 일괄 반영되도록 일원화했습니다. `Users` 테이블에 `token_version` 컬럼(기본값 0)을 추가하고, JWT 토큰을 발행할 때 payload에 현재의 `token_version`을 포함시킵니다.
3. **세션 강제 만료 로직**:
   - 관리자가 사원의 정보를 수정(권한 강등/변경, 비활성화)하거나 패스워드를 초기화할 때, 사용자가 본인의 패스워드를 직접 변경할 때, **그리고 비상용 관리자 비밀번호 초기화 CLI(--reset-admin)나 스크립트를 기동할 때** 대상 사원의 `token_version` 값을 1씩 증가(increment)시킵니다.
   - 요청 검증 미들웨어(`dependencies.py`의 `get_current_user`)에서 토큰에 담긴 `token_version`과 DB의 최신 `token_version` 값을 비교하여, 불일치할 시 `NotAuthenticatedException`을 발생시켜 기존 구버전 토큰 세션을 실시간으로 강제 만료 처리합니다.
   - 토큰 버전을 제공하지 않는 레거시 토큰 또는 테스트용 하드코딩 토큰과의 하위 호환성을 확보하기 위해, 토큰 버전이 없을 때는 0으로 취급하여 대조합니다.

### 6.14 Excel 다중 시트 다운로드 타입 포맷팅 정밀화 (Excel Export Formatting Refinement)
1. **문제 정의**: 연차 타임라인 엑셀 다운로드 파일 내의 수치 데이터(총 배정, 사용 완료, 결재 대기, 잔여 시간) 및 날짜/시간 데이터가 텍스트 형식으로 삽입되어 엑셀 프로그램 내에서 자동 합계(`SUM`), 날짜 정렬, 날짜 간 차이 수식 계산이 불가능한 현상이 있었습니다.
2. **수치 데이터 명시적 형 변환**: 엑셀 시트에 기록되는 총 배정 시간, 사용 완료 시간, 결재 대기 시간, 잔여 시간 및 차감시간 등의 실수/정수 데이터들을 `float`/`int` 타입으로 명확히 변환하여 입력함으로써 엑셀 상에서 수식 연산이 즉시 가능하도록 개선했습니다.
3. **날짜/시간 객체 및 넘버 포맷 지정**:
   - 신청 시각 및 연차일을 문자열이 아닌 `datetime` 및 `date` 객체로 입력하고, openpyxl의 `WriteOnlyCell`를 활용하여 각각 `yyyy-mm-dd hh:mm:ss`, `yyyy-mm-dd` 서식을 명시적으로 지정했습니다.
   - 이를 통해 엑셀 프로그램이 해당 열의 데이터를 온전한 날짜/시간 포맷으로 인식하여 날짜별 정렬, 필터링 및 날짜 연산이 원활하게 작동되도록 최적화했습니다.

### 6.15 데이터베이스 예외 정밀 핸들링 및 사용자 친화적 오류 메시지 연동 (Database Exception Formatting & Resilience)
1. **트랜잭션 롤백 안정성 확보**: 모든 어드민 Write API에 명시적인 `try-except SQLAlchemyError` 블록을 탑재하여 SQLite 동시 쓰기 락 충돌이나 제약 조건 위반 발생 시 즉시 `db.rollback()`이 수행되도록 리팩토링했습니다.
2. **상세 오류 포맷터**: `utils.py`에 `format_db_error_message(exc)` 헬퍼를 추가하여 데이터베이스 수준의 기술 오류를 현업 사용자가 이해하기 쉬운 상세 오류 안내로 자동 파싱합니다.
   - `IntegrityError`: 데이터 중복 또는 연관 데이터 오류로 분기 처리.
   - `OperationalError` (locked/timeout): "데이터베이스가 다른 작업으로 인해 일시적으로 잠겨 있습니다. 잠시 후 다시 시도해 주세요."로 안내.
   - 기타 `SQLAlchemyError`: 예외 객체의 클래스명을 괄호에 표기하여 예쁜 500 에러 JSON 응답을 전송하도록 구조를 강화했습니다.

### 6.16 기본 패스워드(0000) 노출 계정 대상 권장 보안 배너 (Default Password Security Banner)
1. **문제 정의**: 계정 생성 또는 비상 비밀번호 초기화 직후 설정되는 기본 비밀번호 `0000`을 그대로 유지하는 경우, 악의적인 대입 없이도 타인의 계정에 쉽게 진입할 수 있어 보안 위협이 발생합니다.
2. **성능 고려형 플래그 주입**: 매 페이지 요청마다 Bcrypt 비밀번호 검증(`verify_password`)을 돌릴 경우, CPU 해싱 연산 오버헤드로 인해 응답 지연이 심해지므로 로그인 시 1회만 판별하여 JWT 토큰 payload에 `is_default_password` 플래그로 저장합니다.
3. **무헤드 전역 템플릿 연동**: 요청 검증 미들웨어에서 추출한 플래그 값을 `request.state`에 임시 적재한 후, Jinja2 글로벌 컨텍스트 프로세서(`branding_template_context`)를 통해 별도의 DB 조회 오버헤드 없이 모든 템플릿에서 `{{ is_default_password }}` 전역 변수로 바로 사용할 수 있도록 설계했습니다.
4. **시각적 경고 및 즉시 대응**: 기본 비밀번호를 사용하는 계정으로 로그인 시 `base.html` 레이아웃 최상단에 앰버 색조의 보안 권고 배너가 출력되며, 배지 우측의 "비밀번호 변경" 버튼 클릭 시 관리자/사용자 각각의 비밀번호 변경 레이어 모달창을 즉시 호출하도록 구현했습니다.
