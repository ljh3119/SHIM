# 운영 릴리즈 1페이지 체크리스트 (Release Checklist)

이 문서는 운영 담당자가 새로운 버전을 릴리즈할 때 실수를 방지하고 모든 단계를 누락 없이 수행할 수 있도록 돕는 실무 요약본입니다.

---

## 🏁 A. 릴리즈 준비 (Pre-release)
- [ ] 현재 운영 중인 버전 확인 및 신규 버전 넘버링 (예: `1.7.1`)
- [ ] 로컬 개발 환경 및 Docker Desktop 기동 상태 확인
- [ ] 프로젝트 루트 디렉터리(`SHIM/`) 진입

## 🏗️ B. 빌드 및 자동화 검증 (Build & Verify)

### B-1. 사전 안정성/성능 검증 (Pre-Build Safety Test)
릴리즈 빌드 전에 런타임 특수 테스트를 먼저 가동하여 안전성을 점검합니다.
- [ ] 종료 안정성 테스트 통과: `python tools/scripts/test_graceful_shutdown.py`
- [ ] 중복 실행 방지 테스트 통과: `python tools/scripts/test_duplicate_execution.py`
- [ ] 메모리 누수 테스트 통과: `python tools/scripts/test_memory_leak.py`

### B-2. 통합 빌드 및 동기화
다음 통합 명령어를 실행하여 버전 동기화, 이미지 빌드, 코드 정합성 검사를 일괄 수행합니다.

```powershell
.\tools\scripts\release.ps1 -Version 1.7.1 -BuildImage -RunChecks
```
- [ ] 실행 결과 "Release process completed successfully" 메시지 확인
- [ ] 생성된 Docker 이미지 확인: `shim:1.7.1`, `shim:latest`
- [ ] 문서-코드 버전 일치 여부 재확인: `.\tools\scripts\verify_version_sync.ps1`


## 🧪 C. 스테이징 환경 점검 (Staging Test)
운영 반영 전 로컬 컨테이너에서 최종 동작을 확인합니다.

- [ ] 운영 모드 컨테이너 기동: `.\tools\scripts\docker.ps1 up-prod`
- [ ] 주요 엔드포인트 응답 확인 (HTTP 200):
  - [ ] 메인화면 (`/`)
  - [ ] API 문서 (`/docs`)
  - [ ] 정적 자산 (`/static/css/tailwind.css`)
- [ ] 관리자 계정 로그인 및 대시보드 데이터 로딩 확인

## 📦 D. 반입 산출물 준비 (Deployment Artifacts)

### D-1. Docker 이미지 반입 (폐쇄망용)
```powershell
docker save -o shim_1.7.1.tar shim:1.7.1
```
- [ ] `.tar` 파일 생성 및 파일명/버전 일치 확인

### D-2. 포터블 실행본 빌드
```powershell
powershell -ExecutionPolicy Bypass -File .\portable\build_portable.ps1
```
- [ ] `dist/SHIM_Portable/SHIM_Portable.exe` 기동 및 시스템 트레이 제어(브라우저 호출, 트레이를 통한 종료) 확인
- [ ] `data/secret.key` 생성 및 서버 기동 여부 확인 후 프로세스 종료

## 🛡️ E. 최종 보안 점검 (Security Audit)
- [ ] 운영 서버의 `.env`에 고유한 `SHIM_SECRET_KEY`가 적용되었는가?
- [ ] 기본 관리자(`admin`)의 비밀번호가 변경되었는가?
