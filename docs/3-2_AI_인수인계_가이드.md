# 유지보수 및 인수인계 가이드 (Maintenance Standards)

이 문서는 SHIM 프로젝트를 이어받을 개발자 및 AI 에이전트가 준수해야 할 기술적 기준과 작업 표준을 정의합니다. 시스템의 일관성과 안정성을 유지하기 위해 아래 원칙을 반드시 준수하십시오.

---

## 🛠️ 1. 핵심 기술 스택 및 환경
- **Runtime**: Python 3.10+
- **Backend**: FastAPI (Sync routers to safely handle synchronous DB calls with SQLAlchemy within internal threadpool)
- **Database**: SQLite (WAL Mode enabled)
- **Frontend**: Jinja2 + Tailwind CSS v4 (No external CDN allowed)
- **Authentication**: JWT via HttpOnly Cookie (`access_token`)

---

## 📜 2. 개발 및 수정 원칙 (Development Rules)

### ❌ 절대 금지 사항
- **DB 엔진 교체**: SQLite 외의 다른 DB(MySQL, PostgreSQL 등)로의 전환은 아키텍처 결정을 수반하므로 금지합니다.
- **외부 의존성 추가**: 폐쇄망 운영이 기본이므로, CDN 또는 런타임 중 외부 API 호출이 필요한 라이브러리 추가를 금지합니다.
- **대규모 리팩토링**: 사전에 협의되지 않은 폴더 구조 변경이나 전역적 변수명 치환은 지양합니다.

### ✅ 준수 사항
- **프레임워크 전환**: FastAPI 외의 다른 웹 프레임워크 사용을 자제합니다.
- **시간 정책 및 생략**: 시작/종료 시각 입력 기반 신청 방식을 유지하되, 다수일 및 하루종일 신청 시에는 빈 시간값(`""`)을 수용합니다. 이때는 시스템 설정을 자동 파싱하여 8시간 차감 연차로 매핑합니다.
- **SystemSettings 인메모리 캐싱**: 매 HTTP 요청마다 발생하는 중복 DB 조회를 막기 위해 전역 변수 캐싱(`_SYSTEM_SETTINGS_CACHE`)을 도입했습니다. 설정 변경 API 호출 시에만 캐시가 강제 리프레시(`force_reload=True`)되도록 리액션을 보장합니다.
- **N+1 쿼리 방지**: 목록 렌더링 루프 내에서 개별 DB 조회를 지양하고, 사전 Bulk IN 쿼리를 통해 데이터를 O(1) 매핑 딕셔너리로 조회하여 처리하십시오.
- **Dense UI 시스템**: 새로운 화면 추가 시 반드시 기존의 `dense-*` 유틸리티와 토큰(`app.css`)을 활용하여 시각적 일관성을 유지합니다.
- **감사 로그(Audit)**: 시스템 설정 변경, 사용자 비밀번호 초기화, 결재 상태 변경 등 주요 이벤트는 반드시 `AuditLogs`에 기록합니다.
- **버전 동기화**: 수정 후 반드시 `release.ps1`을 실행하여 전체 버전 정보를 동기화합니다.

## 📂 3. 주요 코드 구조 및 역할

| 디렉터리/파일 | 역할 설명 |
|:--- |:--- |
| `src/app/main.py` | 앱 진입점, 미들웨어, 초기화(Seeding) 및 마이그레이션 로직 |
| `src/app/models.py` | SQLAlchemy 테이블 모델링 및 인덱스 정의 |
| `src/app/auth.py` | JWT 발행, 검증 및 암호화 관련 서비스 |
| `src/app/services/` | 비즈니스 로직(연차 계산, 결재 전이 등) 독립 레이어 |
| `src/app/routers/` | API 엔드포인트 및 화면 템플릿 렌더링 컨트롤러 |
| `src/static/css/` | Tailwind CSS 입력(`app.css`) 및 출력(`tailwind.css`) 산출물 |

## 🧪 4. 검증 및 테스트 세트 (Test Suite Guide)

시스템 검증은 목적과 실행 빈도에 따라 **수시 기능 테스트**와 **릴리즈 성능/안정성 테스트**로 나누어 운영합니다. 개발 환경 구동 및 테스트 전용 패키지(`psutil`, `requests`) 설치를 위해 반드시 `requirements-dev.txt`를 사용하십시오.

### 4-1. 개발 환경 패키지 설치
```powershell
pip install -r requirements-dev.txt
```
*주의: 배포 환경(`requirements.txt` 및 Docker 이미지, 포터블 바이너리)에는 개발용 라이브러리가 제외되도록 완벽히 격리되어 있습니다.*

### 4-2. 테스트 케이스 분류 및 실행 명령어

| 구분 | 목적 | 실행 명령어 | 권장 실행 시점 |
|:--- |:--- |:--- |:--- |
| **코드 정합성 검사** | 모듈 컴파일 오류 조기 감지 | `python -m compileall src/app tools/scripts` | 코드 수정 즉시 |
| **비즈니스 로직 검증** | 권한(RBAC), 연차 신청/차감 등 무결성 테스트 (19종) | `python tools/scripts/run_remaining_tests.py` | 코드 수정 즉시 (수초 내 완료) |
| **안정성/종료 검증** | Graceful Shutdown 및 DB Teardown/머지 상태 확인 | `python tools/scripts/test_graceful_shutdown.py` | 릴리즈/배포 전 필수 |
| **중복 실행 방지 검증** | Mutex 기반 런처 다중 기동 차단 및 트레이 알림 연동 확인 | `python tools/scripts/test_duplicate_execution.py` | 릴리즈/배포 전 필수 |
| **메모리 누수 검증** | 장기 가동 시 누적 메모리 및 엑셀 내보내기 성능 확인 | `python tools/scripts/test_memory_leak.py` | 릴리즈/배포 전 필수 |
| **CSS 정적 자산 빌드** | Tailwind CSS 스타일 반영 | `npm run build:css` | UI 수정 시 |
