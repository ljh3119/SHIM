# AI 인수인계 가이드

이 문서는 다른 AI 또는 개발자가 SHIM 작업을 이어받을 때 지켜야 할 기준입니다. 작업 전 반드시 이 문서와 `docs/3-1_향후_개선계획.md`를 먼저 확인합니다.

## 현재 기준

- 현재 릴리스: v1.2.0
- 기본 운영 경로: Docker
- 예외 운영 경로: 포터블 실행본
- DB: SQLite, `var/data/shim_internal.db`
- 웹 프레임워크: FastAPI
- 화면: Jinja2 템플릿 + 로컬 Tailwind CSS 산출물, **Dense UI 토큰·레이아웃**(v1.2.0 기준 핵심 화면에 반영됨)

## 반드시 지킬 원칙

- DB 엔진을 교체하지 않습니다.
- FastAPI 외 프레임워크로 전환하지 않습니다.
- 대규모 폴더 구조 변경을 하지 않습니다.
- 외부 CDN, 외부 API, 런타임 외부 네트워크 의존을 추가하지 않습니다.
- 운영 DB를 테스트 중 직접 변경하지 않습니다.
- 결재 기능 확장은 `can_approve` 기반 추가 결재자 지정까지만 허용합니다.
- 다단계 결재, 대리결재, 결재권자 풀/순번 기반 확장은 현재 범위에서 제외합니다.
- 연차 신청은 시작시간/종료시간 입력 기반이며, 입력 시각은 정책 단위(30/60/120분) 경계값만 허용하고 업무시간 범위 및 최소 신청시간 검증을 함께 적용합니다.
- 슬롯 기반 신청(`slot_ids`, `time_slots`) 또는 병합 정책(`LeavePolicies`) 재도입은 별도 승인 없이 진행하지 않습니다.
- 반려(`REJECTED`) 사유 정책은 최대 500자, 공백-only 입력 금지, 사유 컬럼 무인덱스, `status` 중심 조회 원칙을 유지합니다.
- 기존 URL, 응답 형식, 주요 화면 흐름을 유지합니다.
- Dense UI는 v1.2.0에서 **1차 범위**(로그인·공통 레이아웃, 관리자 shell/대시보드·타임라인·캘린더, 사용자 대시보드, 사원·공휴일·마스터 등)까지 반영되어 있습니다. 이후 수정·추가 화면은 동일 토큰(`dense-*`, `src/static/css/app.css` `@theme`)과 레이아웃 패턴을 맞추고, 시각 참고가 필요하면 `design/ui-handoff`(정적 시안·`directing` Markdown)를 씁니다.
- 기능 추가 전후로 문서와 검증 결과를 동기화합니다.

## 작업 시작 순서

1. `README.md`에서 현재 버전과 실행 경로를 확인합니다.
2. `docs/0_문서_인덱스.md`에서 문서 역할을 확인합니다.
3. `docs/3-1_향후_개선계획.md`에서 이번 작업 항목 하나를 고릅니다(UI만 손볼 때도 Dense 토큰·기존 URL 유지 원칙을 따릅니다).
4. 관련 코드 파일을 읽고 현재 구현 방식을 먼저 파악합니다.
5. 작은 단위로 수정합니다.
6. 검증 후 완료된 내용은 `docs/2-1_운영_릴리즈_통합_산출물.md`에 반영합니다.

### 버전 릴리즈 기본 명령

버전 변경은 수동 치환 대신 아래 스크립트를 우선 사용합니다.

```powershell
.\tools\scripts\release.ps1 -Version 1.2.0 -BuildImage -RunChecks
```

- 버전 문자열 동기화 대상: `package.json`, `src/app/main.py`, `src/templates/base.html`, `infra/docker/docker-compose*.yml`
- Docker 태그 정책: `shim:1.2.0` + `shim:latest`

## 주요 파일

- `src/app/main.py`: 앱 생성, 템플릿/정적 경로, startup 마이그레이션, 기본 데이터 시드
- `src/app/auth.py`: JWT, 비밀번호 해시, `SHIM_SECRET_KEY`
- `src/app/models.py`: SQLAlchemy 모델과 핵심 인덱스
- `src/app/database.py`: SQLite DB 경로와 WAL 설정
- `src/app/services/leave_policy.py`: 연차 정책/검증 서비스 경계
- `src/app/routers/api_admin.py`: 관리자 화면/API
- `src/app/routers/api_user.py`: 사용자 화면/API
- `src/templates/base.html`: 공통 레이아웃, 로컬 CSS 참조
- `src/static/css/app.css`: Tailwind v4 입력 파일
- `src/static/css/tailwind.css`: 배포용 CSS 산출물
- `tools/scripts/run_remaining_tests.py`: 임시 DB 기반 시나리오 테스트
- `tools/scripts/performance_rehearsal.py`: 관리자 인증 기반 운영 규모 응답시간 측정
- `infra/docker/docker-compose.yml`: 운영 Docker 실행 경로
- `infra/docker/docker-compose.dev.yml`: 개발 Docker 실행 경로
- `portable/build_portable.ps1`: 포터블 산출물 빌드

## 검증 기준

기본 검증:

```powershell
python -m compileall src\app tools\scripts
python tools\scripts\run_remaining_tests.py
```

CSS 검증:

```powershell
npm run build:css
```

Docker 검증:

```powershell
$env:SHIM_SECRET_KEY = "운영용_긴_랜덤_문자열"
docker build -f infra/docker/Dockerfile -t shim:1.2.0 -t shim:latest .
docker compose -f infra/docker/docker-compose.yml up -d
```

포터블 검증:

```powershell
powershell -ExecutionPolicy Bypass -File .\portable\build_portable.ps1
.\artifacts\dist\SHIM_Portable\run_portable.bat 8765
```

확인 URL:

- `/`
- `/docs`
- `/static/css/tailwind.css`
- `/favicon.ico`
- 로그인 후 `/admin/dashboard`

## 문서 갱신 규칙

- 완료된 작업과 검증 결과는 `docs/2-1_운영_릴리즈_통합_산출물.md`에 기록합니다.
- 앞으로 남은 작업은 `docs/3-1_향후_개선계획.md`에만 기록합니다.
- 구현 구조나 정책이 바뀌면 `docs/4-1_SHIM_프로젝트_설계서.md`를 갱신합니다.
- 실행 절차가 바뀌면 `docs/1-1_초심자_구동_가이드.md` 또는 `docs/1-2_백업_복구_유지보수_가이드.md`를 갱신합니다.
- 포터블 절차가 바뀌면 `portable/README_PORTABLE.md`를 갱신합니다.
- 문서 목록이 바뀌면 `docs/0_문서_인덱스.md`를 먼저 갱신합니다.
