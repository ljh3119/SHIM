# 향후 개선계획 (Product Roadmap)

이 문서는 아직 완료되지 않은 백로그만 관리합니다. 완료된 변경과 검증 증적은 `docs/2-1_운영_릴리즈_통합_산출물.md`, 변경 후의 현재 설계는 `docs/4-1_SHIM_프로젝트_설계서.md`에서 관리합니다.

---

## 🎯 1. 개발 및 운영 원칙

- 작업 전 `git status --short`와 대상 diff를 확인하고 사용자 미커밋 변경을 보존합니다.
- 새 서비스·서버형 DB·외부 의존성보다 기존 서비스 계층, SQLite 헬퍼와 표준 라이브러리를 우선합니다.
- 로컬 Windows, Docker, 포터블에서 인터넷 없이 동작하는 현재 설계를 유지합니다.
- 재현 테스트를 먼저 추가하고 일부 구현이나 검증이 남으면 완료 처리하지 않습니다.

## 🚀 2. 주요 개선 과제 (Backlog)

### 🟡 [P2] Medium — 개선 권장

- **운영 중인 DB를 위한 안전한 SQLite 스키마 마이그레이션 체계**
  - **배경**: 운영 데이터가 쌓인 뒤 외래키, 인덱스 또는 중요 컬럼을 바꿀 상황에 대비합니다.
  - **개선 방향**: SQLite 제약을 고려해 임시 테이블 복사, 재생성, 검증과 실패 시 복구를 자동화합니다.
  - **완료 기준**: 운영 DB 복제본에서 성공·실패·롤백과 데이터 정합성을 검증합니다.
  - **설계 주의**: 실제 스키마 변경 요구 전 범용 프레임워크를 도입하지 않고 첫 실제 마이그레이션과 함께 최소 도구를 설계합니다.

## ⏳ 3. 장기 보류 및 재검토 과제 (P3)

### 🌐 [P3] 외부망 연동 및 특수 환경 요구 과제
*폐쇄망 및 Zero-Configuration 원칙과 상충할 수 있으므로 별도 인프라가 필요한 구축 사례에서만 재검토합니다.*

- Google / Microsoft OAuth 사내 간편 로그인
- Redmine 연동
- 로그인 무차별 대입 방어 및 계정 잠금
- Nginx/Caddy 프록시 가이드
- 실시간 웹소켓 알림
- 읽기 전용 외부 API

## 🧭 4. 작업 인수인계 규칙

1. 작업 전에 `openwiki/quickstart.md`와 해당 영역 문서를 읽습니다.
2. 한 번에 하나의 작업 ID를 선택합니다.
3. 먼저 재현 테스트를 추가해 현재 코드에서 실패하는지 확인합니다.
4. `git status --short`와 대상 diff를 확인하고 사용자 미커밋 변경을 보존합니다.
5. 새 의존성이나 추상화보다 기존 서비스와 표준 라이브러리를 우선합니다.
6. 최소 검증은 다음과 같습니다.

```powershell
python -m compileall -q src tools portable
python tools/scripts/verify_version_sync.py
python tools/scripts/run_tests.py smoke
```

7. 운영·포터블 변경 시 다음 검사를 추가합니다.

```powershell
python tools/scripts/run_tests.py release
```

8. 완료 후 해당 항목을 이 문서에서 삭제합니다.
9. 완료 증적은 `docs/2-1_운영_릴리즈_통합_산출물.md`로 이관합니다.
10. 변경된 현재 설계는 `docs/4-1_SHIM_프로젝트_설계서.md`에 반영합니다.
11. 구현 또는 검증이 남으면 완료 처리하지 않고 남은 조건과 차단 사유를 유지합니다.
12. 운영·보안·포터블 동작이 바뀌면 README와 해당 운영 가이드도 같은 작업 ID 안에서 갱신합니다.
