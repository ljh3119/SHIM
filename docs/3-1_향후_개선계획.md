# 향후 개선계획 (Product Roadmap)

이 문서는 SHIM 프로젝트의 중장기 발전 방향과 차기 버전의 백로그를 관리합니다. 300명 규모 및 5년 운영 수준의 소규모 폐쇄망 구동 환경에 필요한 최적의 가성비와 슬림한 포터블 배포 철학(Zero-Configuration)에 맞춰 계획을 현실적으로 조정했습니다.

---

## 🎯 1. 개발 및 운영 원칙
- **Minimalism (초경량성)**: 외부 환경이나 추가 의존성 없이 장기 구동이 가능하도록 외부 종속성을 철저히 제한합니다.
- **Lightweight Portable (슬림한 배포)**: 포터블 바이너리(`SHIM_Portable.exe`)의 기동 속도와 런타임 성능을 최적화하기 위해, 구동에 불필요한 서드파티 라이브러리 및 임포트 의존성을 전면 배제하여 순수하게 유지합니다.
- **Verification**: 모든 기능 추가 시 `tools/scripts` 내 검증 시나리오를 동기화하여 안정성을 보장합니다.
- **Consistency**: 기존의 시간 정책(30/60/120분 단위)과 Dense UI 디자인 시스템의 고유 정체성을 준수합니다.

## ⏳ 3. 장기 보류 및 재검토 과제 (P3)

### [P3] 기획 검토 및 철학적 조율 필요 과제
- **비밀번호 강도 최소화 검증 기준 보강**:
  - 현재 비밀번호 자가 변경 시 최소 4자 이상이라는 매우 단순한 정책을 가지고 있으나, 보안 요구 수준에 맞춘 비밀번호 복잡도 규칙이나 기준을 강화할 수 있도록 기획 설계를 보완하는 개선안을 보류 과제로 등록합니다.
- **Option G 데스크톱 뷰 내 좌측 사이드바 미니 목록(결재 대기/나의 신청) 제거를 통한 UI 중복 해소**:
  - **현황**: 현재 구현된 Option G는 우측 메인 영역(캘린더, 타임라인, 결재 관리 탭)에서 모든 신청 내역과 결재 관리가 대화형으로 연동되므로, 좌측 사이드바 패널 내의 미니 결재 대기 목록과 나의 신청 내역이 기능적으로 중복 노출됩니다.
  - **개선 제안**: 이 두 가지 미니 목록 카드를 좌측 영역에서 완전히 제거하여 좌측 영역은 순수하게 '나의 상태 요약 + 간편 신청 입력 폼'의 역할로 한정하고, 가로폭 및 세로 배치 가독성을 최적화합니다.
- **개인 페이지 타임라인 뷰 내 중복 뷰 전환 토글 제거**:
  - **현황**: 개인 페이지 - 타임라인 뷰(연차 캘린더 타임라인 탭)에서 화면 상단의 메인 탭바에 이미 '타임라인'이 선택된 상태임에도 불구하고, 하단의 메인 카드 영역 우측 상단에 여전히 '타임라인 / 캘린더 뷰' 전환 토글 버튼이 다시 노출되어 UI 흐름상 중복되고 어색한 사용자 경험을 유발합니다.
  - **개선 제안**: 타임라인 뷰의 카드 내부에 있는 중복 뷰 전환 토글을 제거하거나 레이아웃을 정돈하여, 상단 메인 탭 전환 흐름과 자연스럽게 일치하도록 개선합니다.


### 🌐 [P3] 외부망 연동 및 특수 환경 요구 과제 (최후순위 보류)
*SHIM의 핵심 정체성인 '오프라인 폐쇄망 최적화 및 제로 컨피그' 철학과 상충될 여지가 있는 기능들로, 외부 인터넷망 환경이나 별도 인프라 연동이 수반되는 특수 구축 사례에 한해서만 가장 늦게 검토하는 최후순위 과제입니다.*
- **Google / Microsoft OAuth 사내 간편 로그인 연동 (SSO)**:
  - 구글 워크스페이스나 M365 도메인을 사용하는 기업들을 위해 이메일 주소 대조 기반 OAuth 로그인을 플러그인(인터페이스 분리) 형태로 제공하는 방안을 장기 보류 과제로 둡니다.
- **Redmine 등 사내 외부 협업 도구 연동**:
  - Redmine API를 이용해 사용자 정보 동기화 및 패스워드 인증을 수행하는 확장 모듈을 플러그인 형태로 검토하되, 범용성이 제한되므로 최후순위로 미룹니다.
- **로그인 무차별 대입(Brute-Force) 방어 및 계정 잠금 정책 (패스워드 해싱 비용 튜닝 포함)**:
  - 폐쇄망 단독 구동 시에는 무겁고 불필요할 수 있으므로, 외부망 연동이나 외부 노출 시나리오가 수반되는 특수 환경 요구 과제로 편입하여 검토합니다. 단시간 로그인 오시도에 대한 IP 접속 속도 제한(Rate Limiting) 및 계정 임시 잠금 처리와 함께, 저사양 포터블 PC 환경에서 다중 로그인 시 발생하는 CPU 병목을 제어할 수 있도록 해싱 알고리즘(bcrypt)의 rounds 강도를 유연하게 튜닝할 수 있도록 설정 변수화하는 방안을 포함합니다.
- **외부 보안 표준 대응을 위한 프록시(Nginx/Caddy) 연동 가이드 및 충돌 보완 (Docker 템플릿 포함)**:
  - 포터블 자체 HTTPS 내장은 용량 비대화와 포트 통제 권한 오류를 유발하므로 배제하고, Nginx/Caddy 등 표준 프록시를 연동하는 정석 가이드 및 Docker 배포 시 즉시 활용할 수 있는 설정 파일 템플릿(infra/docker)을 제공하되 프록시 통과 시 로그인 쿠키 유실(Secure/SameSite 헤더 미일치) 및 접속 IP 식별 실패(X-Forwarded-For 미인식) 충돌을 백엔드에서 가볍게 흡수해 줄 수 있는 보완 패치를 최후순위로 검토합니다.
- **실시간 웹소켓 알림**:
  - 일반적인 사용 환경 및 폐쇄망에서는 필요성이 낮으므로, 향후 외부망 연동 등 대규모 업데이트 로드맵이 그려지는 시점까지 검토를 보류합니다. (상세 내용은 하단의 [실시간 알림 보류 계획](#p3-외부망-연동-및-특수-환경-요구-과제-최후순위-보류) 참조)

## 4. 모던 ERP 비교 분석 및 개선 제안 (v1.7.3 기준)

이 섹션은 SHIM 프로젝트의 현재 포지션을 글로벌/국내 모던 HR 솔루션과 비교 분석하고, UI/UX 개선안 및 기능 추가 후보를 도출한 분석 내용을 담고 있습니다.

### 4.1 분석 목적 및 비교 대상

#### 목적
SHIM 프로젝트가 현재 개발 중인 방향이 모던 ERP들의 휴가 관리 방안과 어떻게 다르고, 어떤 점이 고려 사항인지를 체계적으로 정리하여 향후 로드맵 수립의 기초 자료로 활용합니다.

#### 비교 대상
| 계층 | 대표 솔루션 | 특성 |
|:---|:---|:---|
| **글로벌 엔터프라이즈** | Workday, SAP SuccessFactors | 대규모 조직, 복잡한 글로벌 컴플라이언스 |
| **글로벌 SMB SaaS** | BambooHR, Personio | 중소기업 특화, 뛰어난 UX, 클라우드 네이티브 |
| **한국 특화 SaaS** | 시프티(Shiftee), 플렉스(flex) | 한국 노동법/연차 촉진제도 등 로컬 규정 대응 |

---

### 4.2 SHIM의 포지셔닝 분석

#### 포지션 요약
SHIM은 모던 ERP와 **같은 시장에서 경쟁하지 않는** 독자적인 포지션을 점유하고 있습니다:
- **모던 ERP 방향**: 더 많은 기능 → 더 넓은 통합 → 더 깊은 AI
- **SHIM 방향**: 더 적은 의존성 → 더 좁은 초점 → 더 강한 자율성

```
  ┌─────────────────────────────────────────────────┐
  │                                                 │
  │   🔌 Zero-Configuration                        │
  │   → EXE 더블클릭만으로 전체 시스템 기동         │
  │                                                 │
  │   🔒 Complete Data Sovereignty                  │
  │   → 데이터가 로컬 PC를 벗어나지 않음             │
  │                                                 │
  │   🏗️ Multi-Company First                        │
  │   → 컨소시엄 환경을 1차 시민으로 설계            │
  │                                                 │
  │   📡 Offline-First                              │
  │   → 인터넷 없이 완전한 기능 운영                 │
  │                                                 │
  │   🛡️ Self-Healing                               │
  │   → IT 관리자 없이도 자가 복구/백업              │
  │                                                 │
  └─────────────────────────────────────────────────┘
```

#### 핵심 성공 기준
SHIM의 성공 기준은 "BambooHR만큼 기능이 많은가"가 아니라, **"폐쇄망 현장 PM이 3분 안에 '오늘 누가 쓸 수 있는 인력인가'를 파악할 수 있는가"**입니다.

---

### 4.3 비교 축별 심층 분석

#### 배포 및 인프라
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **배포 모델** | 클라우드 SaaS (인터넷 필수) | 로컬 SQLite + 포터블 EXE |
| **초기 설정 비용** | 계약 → 온보딩 → 설정 (수주~수개월) | 폴더 복사 → 더블클릭 (수 분) |
| **인프라 의존성** | 클라우드 서버, CDN, DB 서버 | **없음** (Zero-Configuration) |
| **오프라인 운영** | ❌ 불가 | ✅ 완전 지원 |
| **데이터 주권** | 벤더 클라우드에 저장 | 로컬 PC 내 물리 파일 |

> **SHIM만의 강점**: 폐쇄망/건설 현장/군사 시설 등 인터넷 접속이 물리적으로 불가능한 환경에서 운영 가능한 연차 관리 도구는 시장에서 거의 존재하지 않습니다.

#### 다중 조직 관리
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **다중 회사 지원** | Multi-Entity 라이선스 (별도 비용) | ✅ 기본 내장 (Company/Team 배지) |
| **팀 간 가시성** | 조직도 기반 계층형 | 3단계 공유 수준 (none/team/company) |
| **컨소시엄 지원** | 설계 미고려 | ✅ 핵심 설계 목표 |

> **차별점**: 대부분의 모던 ERP는 **단일 법인** 기준으로 설계되어, 다중 회사 컨소시엄 시나리오에서 별도 라이선스나 복잡한 Multi-Entity 설정이 필요합니다. SHIM은 이를 **1차 시민(First-Class)**으로 다루며, HSL 해시 기반 동적 배지로 시각적 식별까지 해결합니다.

#### 연차 차감 엔진 정밀도
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **차감 단위** | 일/반일 (일부: 시간 단위) | 30/60/120분 정밀 단위 |
| **점심시간 자동 제외** | 일부 지원 | ✅ 기본 내장 |
| **비차감 구분 (공가/출장)** | 별도 부재 유형 모듈 | ✅ `is_deductive` 플래그로 통합 |
| **정책 스냅샷** | ❌ (변경 시 소급 영향) | ✅ 신청 시점의 정책 보존 |

> **정책 스냅샷**: 모던 ERP에서도 드문 기능입니다. 대부분의 시스템은 정책이 변경되면 과거 신청 건의 산정 근거가 바뀌지만, SHIM은 `snapshot_*` 필드로 신청 시점의 정책을 고정하여 감사 추적성과 법적 안전성을 확보합니다.

#### 결재 워크플로우
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **워크플로우 복잡도** | 다단계 (팀장→부장→HR) | **단선 결재** (1단계) |
| **자동 라우팅** | AI 기반 스마트 라우팅 | RBAC 기반 (TEAM_LEAD/PM) |
| **셀프 결재 방지** | 일반적으로 지원 | ✅ 팀장 셀프 결재 금지 |
| **PM 자동 승인** | 커스텀 설정 필요 | ✅ 기본 내장 |

> **고려사항**: 단선 결재는 소규모 팀(30~50명)에서는 충분하지만, 100명 이상의 조직에서는 "팀장 부재 시 대결" 시나리오가 현실적으로 빈번합니다. PM의 전사 결재권으로 우회하고 있으나 모든 조직 문화에 부합하는지는 검토가 필요합니다. (상세 내용은 설계서의 결재 권한 운영 모델을 참조하십시오.)

#### 사용자 경험 (UX)
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **인터페이스** | SPA (React/Vue), 모바일 앱 | SSR (Jinja2 + Dense UI) |
| **모바일 대응** | 네이티브 앱 또는 PWA | 반응형 웹 (sm:/md: 대응) |
| **셀프서비스** | 잔여 연차 실시간 조회, 챗봇 | ✅ 대시보드 잔여 조회 |
| **챗봇/NLU** | WhatsApp/Slack 연동 | ❌ 범위 외 |

> **참고**: 모바일 앱 부재는 SHIM의 **의도적 설계 결정**입니다. 폐쇄망에서는 앱 스토어 접근이 불가능하고, PWA 역시 서비스워커 등록에 HTTPS가 필요하므로 포터블 HTTP 환경과 상충합니다.

#### 보안 및 개인정보 보호
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **인증** | OAuth2/SSO/MFA | JWT (HttpOnly Cookie) |
| **PII 보호** | 서버 사이드 암호화 + 접근 제어 | ✅ Fernet 대칭 암호화 (`EncryptedString`) |
| **감사 추적** | 기본 제공 | ✅ Actor 스냅샷 포함 감사 로그 |
| **세션 무효화** | 서버 사이드 세션 관리 | ✅ `token_version` 기반 즉시 만료 |
| **데이터 주권** | 벤더 서버 (GDPR 등 규정 준수) | ✅ 로컬 물리 파일 완전 통제 |

> **SHIM의 PII 보호 설계**: 대부분의 SaaS는 "우리 서버가 안전합니다"에 의존하지만, SHIM은 DB 파일 탈취 시나리오까지 고려하여 컬럼 단위 Fernet 암호화 + 비밀키 일관성 Fail-Fast 검증을 구현했습니다.

#### 운영 안정성 및 자율 복구
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **백업** | 벤더가 관리 (SLA 기반) | ✅ 자가 핫 백업 (1시간 + Write 트리거) |
| **장애 복구** | 벤더 SLA, DR 센터 | ✅ 기동 시 자가 복구 (`quick_check` + `.bak` 복원) |
| **DB 무결성 검증** | 벤더 인프라 레벨 | ✅ `PRAGMA quick_check` 기동 검사 |
| **마이그레이션** | Alembic/Liquibase/벤더 자동 | ✅ 자체 DDL 마이그레이션 엔진 |

#### 성능 설계
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **동시성** | 수천~수만 동시 사용자 | SQLite WAL (수십~수백) |
| **캐싱** | Redis/Memcached | ✅ 인메모리 `_SYSTEM_SETTINGS_CACHE` |
| **N+1 방지** | ORM Eager Loading | ✅ Bulk Query + 메모리 맵핑 |
| **대용량 엑셀** | 서버 사이드 스트리밍 | ✅ `WriteOnlyWorkbook` 10MB 고정 |

- **현재 격차**: 본인의 연차가 승인/반려되었는지 확인하려면 직접 대시보드에 접속해야 합니다.
- **제안 (폐쇄망 호환)**:
| 방식 | 설명 | 장점 | 단점 |
|:---|:---|:---|:---|
| **① DB 알림 테이블** | 승인/반려 시 `Notifications` 테이블에 INSERT → 대시보드 미확인 카운트 표시 | 가장 단순, SSR 호환 | 페이지 새로고침 필요 |
| **② 폴링 기반 배지** | 30초 간격 `/api/user/unread-count` 호출 → 사이드바 벨 아이콘 업데이트 | 유사 실시간 | SQLite 경량 쿼리로 부하 미미 |
- **권장**: ① DB 알림 테이블 + ② 30초 폴링 조합. (실시간 웹소켓/SSE 보류 사유는 [실시간 알림 보류 계획](#p3-외부망-연동-및-특수-환경-요구-과제-최후순위-보류) 참조).
- 난이도: **중**
- 핵심 가치: "신청했으나 결과를 모른다"는 현재 UX의 가장 큰 단절 포인트 해소

#### 4.6.5 개인 연차 변경 이력 타임라인 (사용자)
- **현재 격차**: `user_history.html`에 신청 건 목록만 표시되어, 상태 변경 이력을 시간순으로 확인할 수 없습니다.
- **제안**: 각 신청 건에 확장 가능한 아코디언으로 AuditLogs 연계 상태 변경 타임라인 표시.
```
[2026-06-10 09:15]  신청됨
[2026-06-10 14:30]  팀장 김철수 승인  ✅
```
- 난이도: **중** (AuditLogs 연계 쿼리 + 프론트엔드 아코디언)

#### 4.6.6 읽기 전용 API 엔드포인트
- **현재 격차**: 모든 데이터가 SSR 템플릿에 묶여 있어 외부 활용이 불가합니다.
- **제안**:
  - `/api/v1/availability` — 특정 날짜/팀의 가용 인력 조회
  - `/api/v1/calendar` — 특정 월의 전사/팀별 연차 데이터 JSON 반환
  - 기존 JWT 쿠키 인증 그대로 사용
- **활용 시나리오**: 사내 포탈 위젯 임베드, Excel VBA 자동 보고서, 타 프로젝트 관리 도구 연동
- 난이도: **하~중** (기존 서비스 레이어 재활용)

### 4.8 최종 평가

SHIM은 모던 ERP가 커버하지 못하는 **폐쇄망/컨소시엄/제로컨피그** 니치 시장에서 대체 불가능한 가치를 제공하고 있습니다.

기능 확장 시에는 반드시 아래 원칙을 견지해야 합니다:
1. **외부 의존성 추가 금지** — 폐쇄망 운영 철학 유지
2. **포터블 바이너리 무결성** — 신규 기능이 EXE 크기/기동 속도에 미치는 영향 검증
3. **Dense UI 정체성 준수** — 기존 디자인 토큰 체계 활용, 일관된 시각 언어 유지
4. **핵심 질문에 충실** — "오늘 누가 쓸 수 있는 인력인가"를 3분 안에 답할 수 있는가
