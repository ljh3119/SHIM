# 향후 개선계획 (Product Roadmap)

이 문서는 SHIM 프로젝트의 중장기 발전 방향과 차기 버전의 백로그를 관리합니다. 300명 규모 및 5년 운영 수준의 소규모 폐쇄망 구동 환경에 필요한 최적의 가성비와 슬림한 포터블 배포 철학(Zero-Configuration)에 맞춰 계획을 현실적으로 조정했습니다.

---

## 🎯 1. 개발 및 운영 원칙
- **Minimalism (초경량성)**: 외부 환경이나 추가 의존성 없이 장기 구동이 가능하도록 외부 종속성을 철저히 제한합니다.
- **Lightweight Portable (슬림한 배포)**: 포터블 바이너리(`SHIM_Portable.exe`)의 기동 속도와 런타임 성능을 최적화하기 위해, 구동에 불필요한 서드파티 라이브러리 및 임포트 의존성을 전면 배제하여 순수하게 유지합니다.
- **Verification**: 모든 기능 추가 시 `tools/scripts` 내 검증 시나리오를 동기화하여 안정성을 보장합니다.
- **Consistency**: 기존의 시간 정책(30/60/120분 단위) 및 Dense UI 디자인 시스템의 고유 정체성을 준수합니다.

---

## 🚀 2. 주요 개선 과제 (Backlog)

현재 모든 단기 개선 과제(알림 센터, KPI 통계, 변경 이력 타임라인, 브레드크럼, 상대 시간, 어드민 대시보드 시스템 운영 현황 카드 개선 등)는 모두 성공적으로 구현 완료(v1.8.5)되어 운영/릴리즈 통합 산출물 (Release Ledger)로 이관되었습니다.

추후 현장 운영 피드백에 따른 경량 신규 과제가 도출될 경우 여기에 백로그로 적재 관리합니다.

### 🌐 [P3] 외부망 연동 및 특수 환경 요구 과제 (최후순위 보류)
*SHIM의 핵심 정체성인 '오프라인 폐쇄망 최적화 및 제로 컨피그' 철학과 상충될 여지가 있는 기능들로, 외부 인터넷망 환경이나 별도 인프라 연동이 수반되는 특수 구축 사례에 한해서만 가장 늦게 검토하는 최후순위 과제입니다.*
- **Google / Microsoft OAuth 사내 간편 로그인 연동 (SSO)**
- **Redmine 등 사내 외부 협업 도구 연동**
- **로그인 무차별 대입(Brute-Force) 방어 및 계정 잠금 정책 (패스워드 해싱 비용 튜닝 포함)**
- **외부 보안 표준 대응을 위한 프록시(Nginx/Caddy) 연동 가이드 및 충돌 보완 (Docker 템플릿 포함)**
- **실시간 웹소켓 알림** (외부망 연동 시 검토)
- **사내 대시보드 및 외연 연동용 읽기 전용 API 엔드포인트** (`/api/v1/availability` 등)

#### ⚡ 현 프로젝트 적용 시 영향도 분석 (Impact Analysis)
- **성능 및 부하 영향 (무시해도 될 수준)**:
  - 파일 용량 확인 및 백업 개수 스캔 시 OS의 동기적 I/O 블로킹 위험을 피하기 위해, 백그라운드 스케줄러가 정보를 주기적으로 확인해 DB에 갱신하거나 `asyncio.to_thread`를 경유해 비동기로 처리하도록 아키텍처를 안전화합니다.
  - 암호화 모드 검사는 메모리에 로드된 암호키 상태(`auth.get_encryption_key()`)만 확인하므로 추가 CPU 소모가 없습니다.
  - 스케줄러 수행 성공 시간은 다중 프로세스(Gunicorn/Uvicorn Multi-Worker) 배포 환경에서 격리된 메모리 간 불일치(Phantom Data)를 원천 해결하기 위해, 메모리 변수 대신 **SQLite 영속 테이블(`system_settings` 등에 컬럼 추가)**에 저장하여 단일 신뢰 소스(Single Source of Truth)를 유지합니다.
- **SQLite 락(Lock) 충돌 제로**:
  - 모두 읽기 위주의 가벼운 처리이며 파일 메타 정보와 메모리 캐시를 경유하므로 SQLite 쓰기 트랜잭션 락(`database is locked`)을 유발할 우려가 전혀 없습니다.
- **의존성 최소화 (Zero-dependency)**:
  - 파이썬 표준 라이브러리(`os`, `pathlib`, `datetime`, `asyncio`)만 사용하므로 외부 서드파티 의존성이 추가되지 않아 포터블 패키징 배포 용량 증가가 전혀 없는 안전한 설계입니다.

#### 🔧 구체적인 개선 및 개발 방향 (Implementation Details)
- **백엔드 리액터 설계**:
  - **다중 워커 상태 동기화**: `last_backup_time`, `last_cleanup_time` 값을 저장할 수 있도록 SQLite 영속 데이터베이스 스키마 마이그레이션 적용 및 스케줄러 성공 시점에 DB에 `UPDATE` 처리.
  - **Uptime 보장**: `src/app/main.py` 구동 시점의 로컬 시각을 전역 변수 `START_TIME`으로 기록 및 유지 (Uptime은 개별 워커에 무관한 기동 시각이므로 메모리 관리로 안전).
  - **WAL 팽창 예방**: 무중단 장기 기동 시 로그 파일의 무한 팽창을 방지하기 위해 `PRAGMA wal_autocheckpoint = 1000;` 설정을 명시적으로 활성화하고, 백업본 작성 및 DB 닫기 직전에 자동 병합이 수행되도록 정교하게 감시.
- **프론트엔드 UI/UX 가이드 (임계치 경고 감지 적용)**:
  - **실패 시 뱃지 강제 전환**: 최종 백업 시간이 26시간을 초과하는 등 스케줄러 오동작/실패 감지 시, 화면의 시스템 활성 표시를 🟢 정상 뱃지 대신 **🔴 실패/지연 경고 뱃지**로 강제 전환하여 장애 가시성 확보.
  - **Dense UI 레이아웃**: 위젯 카드의 크기를 유지하되, 내부를 `grid-cols-2` 또는 세밀한 세로 리스트 형태로 구현하여 가동 시간, 보안 모드, DB 크기, 백업본 상태, 알림 정리 상태를 회색 서브라벨과 촘촘하게 결합하여 표기.
