# 향후 개선계획 (Product Roadmap)

이 문서는 SHIM 프로젝트의 중장기 발전 방향과 차기 버전의 백로그를 관리합니다. 폐쇄망 구동 환경의 특성 및 슬림한 포터블 배포라는 철학에 맞추어 우선순위와 기술 방향성을 조정했습니다.

---

## 🎯 1. 개발 및 운영 원칙
- **Minimalism (초경량성)**: 외부 환경이나 추가 의존성 없이 장기 구동이 가능하도록 외부 종속성을 철저히 제한합니다.
- **Lightweight Portable (슬림한 배포)**: 포터블 바이너리(`SHIM_Portable.exe`)의 기동 속도와 런타임 성능을 최적화하기 위해, 구동에 불필요한 서드파티 라이브러리 및 임포트 의존성을 전면 배제하여 순수하게 유지합니다.
- **Verification**: 모든 기능 추가 시 `tools/scripts` 내 검증 시나리오를 동기화하여 안정성을 보장합니다.
- **Consistency**: 기존의 시간 정책(30/60/120분 단위)과 Dense UI 디자인 시스템의 고유 정체성을 준수합니다.

---

## 🚀 2. 주요 개선 과제 (Backlog)

현재 시스템 완성도 향상과 기능 정밀화를 우선순위로 두고 개발을 이어가고 있습니다.

### [P1] SQLite 데이터베이스 2단계 최적화 분리 설계 (SQLite Optimization Pipeline)
- **목적**: 장기 운용 시 SQLite WAL 파일의 비대화와 파편화로 인한 속도 저하를 방지하되, 무거운 작업으로 인한 초기 앱 기동 지연(UX 결함)을 원천 차단합니다.
- **세부 계획**:
  - **가벼운 기동 최적화 (Lifespan Startup)**: FastAPI의 lifespan 시작 시점에는 부하가 매우 경미한 `PRAGMA wal_checkpoint(TRUNCATE);`만 실행하여 저널 파일(`.db-wal`)을 메인 DB로 즉각 병합하고 0바이트로 초기화합니다.
  - **무거운 조각 모음 격리 (Maintenance VACUUM)**: 파일 전체 복사를 유도하는 무거운 `VACUUM;` 명령어는 기동 시점(startup)에서 배제하고, `backup_db.ps1` 백업 스크립트 실행 직후 또는 시스템 사용이 거의 없는 야간 백그라운드 배치 프로세스 내에서만 한정 수행하도록 안전하게 분리합니다.

### [P2] 일부 API 엔드포인트의 데이터베이스 트랜잭션 롤백 보강
- **목적**: 예외 상황 발생 시 트랜잭션의 원자성을 완벽히 보장하여 데이터 정합성 결함을 예방합니다.
- **세부 계획**:
  - **대상 API 조사 및 적용**: `hard_delete_user`를 포함하여 `db.commit()` 시점에 명시적인 `try-except SQLAlchemyError` 구문 및 `db.rollback()`이 누락된 관리자/사용자 API들을 보완합니다.
  - **오류 전파 방지**: 트랜잭션 커밋 에러 발생 시 세션이 오염된 상태로 방치되지 않도록 즉각 롤백을 지시하고, 사용자에게 500 서버 오류 응답(JSONResponse)을 반환하는 안전핀 코드를 구성합니다.

### [P2] 브랜드 및 시스템 설정 미들웨어 DB 세션 오버헤드 최적화
- **목적**: 매 HTTP 요청 시 수행되는 불필요한 시스템 설정 DB 조회 및 커넥션 열기/닫기 비용을 절감하여 전반적인 API 지연 시간을 개선합니다.
- **세부 계획**:
  - **미들웨어 쿼리 병목 제어**: `src/app/main.py`의 `branding_middleware`에서 정적 자원을 제외한 매 요청마다 동기적으로 데이터베이스 세션을 열어 브랜드 구성을 읽는 구조를 리팩토링합니다.
  - **In-Memory 캐시 및 캐시 무효화 도입**: 자주 바뀌지 않는 `SystemSettings` 테이블의 브랜드 데이터를 메모리에 캐싱하고, 관리자가 설정을 변경할 때만 캐시를 강제 무효화(Invalidate)하는 경량 캐시 헬퍼를 적용합니다.

## ⏳ 3. 장기 보류 및 재검토 과제 (P3)

### [P1] 정식 출시 기준 정비 및 마이그레이션 베이스라인화 (보류)
- **정식 출시 시점의 마이그레이션 스쿼시(Squash) 및 베이스라인화**:
  - 정식 배포 릴리즈 확정 시점(버전 미정) 직전까지 완전히 보류합니다.

  - 기존 테스트/개발 단계에서 적용되었던 점진적 마이그레이션 스텝들(`v1.4.0`, `v1.5.0`, `v1.5.6` 등)을 SQLAlchemy 기본 스키마 정의(`models.Base.metadata.create_all`)로 전면 통합합니다.
  - 정식 버전 이후 실운영 중에 발생하는 스키마 변경 사항만 신규 마이그레이션으로 정의하여 데이터베이스 관리 복잡도를 예방합니다.

### [P3] 기획 검토 및 철학적 조율 필요 과제
- **장기 적재 감사 로그의 아카이브 및 정리(Cleanup) 기능**:
  - 장기 운용 시 SQLite DB 파일의 비대화를 방지하고 최적 성능을 유지할 수 있도록, 1년 이상 경과한 감사 로그를 XLSX/JSON 파일로 아카이브 백업 후 DB에서 삭제하는 배치 기능을 낮은 우선순위로 검토합니다.
- **임시/대체 공휴일 일괄 업로드 기능 검토**:
  - 오프라인/폐쇄망 내에서 임시/대체공휴일이 동적 지정될 때, 관리자의 수동 입력 편의를 위해 공휴일 일괄 업로드 형식을 검토하되, 공휴일 변동 빈도가 매우 낮음을 고려하여 구현 우선순위를 보류합니다.
- **프론트엔드 연차 신청 슬라이더 시간 유효성 실시간 1차 차단**:
  - 사용자가 시간 설정 슬라이더 조작 시 점심시간과 겹치거나 시작-종료 시간의 선후관계 오류로 차감 시간이 0 이하가 되는 상황을 프론트엔드 인터랙션 단에서 실시간 감지하여 신청 버튼을 비활성화하거나 슬라이더 위치를 보정해 주는 화면 단의 실시간 피드백 로직을 보류 과제로 등록합니다.
- **감사 로그 데이터 구조화(JSON화) 여부**:
  - "가볍고 오래 켜둘 수 있는 초경량 시스템"이라는 SHIM의 핵심 철학을 고려할 때, JSON 포맷 도입이 SQLite I/O에 미칠 영향을 재검토하여 텍스트 기반 및 한글 매핑 헬퍼를 유지할지 결정합니다.
- **사원 비활성화 시 미래 연차 처리**:
  - 사원 비활성화 시 미래 연차의 자동 반려가 실무 예외 프로세스(예: 복직 등)와 충돌할 소지가 있으므로 구체적인 기획 검토 완료 후 진행 여부를 결정합니다.
- **실시간 웹소켓 알림**:
  - 일반적인 사용 환경 및 폐쇄망에서는 필요성이 낮으므로, 향후 외부망 연동 등 대규모 업데이트 로드맵이 그려지는 시점까지 검토를 보류합니다.
