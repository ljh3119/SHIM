# 향후 개선계획 (Product Roadmap)

이 문서는 SHIM 프로젝트의 중장기 발전 방향과 차기 버전의 백로그를 관리합니다. 

---

## 🎯 1. 개발 및 운영 원칙
- **Minimalism**: 폐쇄망 환경의 특수성을 고려하여 외부 의존성을 최소화합니다.
- **Consistency**: 기존의 시간 정책(30/60/120분 단위)과 Dense UI 디자인 시스템을 유지합니다.
- **Verification**: 모든 기능 추가 시 `tools/scripts` 내 검증 시나리오를 동기화합니다.

---

## 🚀 2. 주요 개선 항목 (Backlog)

### [P2] 편의 및 확장 과제
- **통계 리포트**: 전사/팀별 연차 사용 현황 엑셀 다운로드 기능 (관리자용)
- **알림 강화**: 자체 웹 화면 내 실시간 웹소켓(WebSocket) 토스트 알림 또는 상단 알림 영역 활용 (폐쇄망 환경이므로 외부 Push 서비스 의존성 있는 브라우저 Web Push API는 전면 배제)
- **접근성 및 UI**:
    - Dense UI 내 고대비 모드 및 키보드 내비게이션 보강
    - 모바일 환경에서의 연차 신청 UX 최적화 (날짜 선택기 개선)
    - **디자인 시스템 통일성 검토**: Dense UI v4 토큰에 부합하도록 전체 화면의 레이아웃, 입력 양식, 드롭다운 필드 및 컴포넌트 간 디자인 통일성을 전수 검토 및 보완
- **[기획 검토 및 방향성 고민 과제] 사원 비활성화 시 미래 연차 건의 자동 처리**: 관리자가 사원을 비활성화(`is_active = False`)할 때, 해당 사원의 오늘 이후 미래 연차 신청 건(`PENDING`/`APPROVED`)을 자동 취소/반려하여 부서별 캘린더 및 연차 통계 왜곡 방지 (비활성화 상태와 자동 취소 동작 간 비즈니스적 예외 케이스 및 방향성 추가 기획 필요)

## 🏗️ 3. 기술 부채 및 아키텍처 과제
- **데이터베이스 및 트랜잭션**:
    - **스키마 마이그레이션 호환성 유지**: Alembic 등의 무거운 도구는 포터블(PyInstaller) 패키징 시 경로 매핑 오류 등 구조적 복잡성을 유발하므로 배제하고, `main.py`의 애플리케이션 기동 시점 DDL 자동 패치(ALTER TABLE 예외 처리 등) 로직을 고도화하여 안전하게 스키마 변경에 대응
    - **대규모 데이터 스케일 아웃 대비 검토**: 향후 장기 운영(5년 이상, 300명 이상의 사원 수적 스케일 업) 시 SQLite의 단일 파일 락 및 동시 쓰기 성능 한계를 모니터링하고, 필요 시 확장형 RDBMS 이관 시나리오를 선제적으로 설계 (현재 기본 환경은 소규모/단일팀 대상 1-바이너리 및 Docker식 SQLite WAL 모드 유지)
    - `AuditLogs` 테이블의 `old_data`, `new_data`를 JSON 포맷으로 전환하여 상세 쿼리 지원
- **성능 및 아키텍처 최적화**:
    - **[기획 검토 및 방향성 고민 과제] FastAPI `async def` 라우터와 동기 SQLAlchemy DB 호출의 조합 병목**: 현재 FastAPI 라우터는 동기식 SQLAlchemy ORM을 호출함에도 `async def`로 선언되어 있어 메인 이벤트 루프를 블로킹할 위험이 있습니다. 500명 미만의 소규모 시스템 환경에서는 성능적 영향이 미미하지만, 동시 요청 급증 시 응답 지연을 방지하기 위해 모든 라우터를 동기식(`def`)으로 전면 전환하여 FastAPI가 내부 스레드풀에서 병렬 처리하도록 구조를 리팩토링할지 방향성을 깊이 있게 검증할 필요가 있습니다.
    - **1-바이너리(EXE) 통합 런처 구현**: 기존 run/stop 배치 파일과 exe 실행 파일을 단 하나의 `SHIM_Portable.exe`로 통합하여 배포 파일 구조를 단순화하고 사용자 경험 향상
        - 기동 방식: 외부 라이브러리 추가 없이 CMD 콘솔 창을 띄워 진행하며, 창을 종료하거나 `Ctrl+C` 입력 시 프로세스가 안전하게 셧다운되도록 설계
        - 포트 충돌 처리: 기본 포트(8000) 사용 중 감지 시, 파이썬 내장 `socket` 라이브러리를 활용해 비어 있는 대체 포트를 신속히 찾아내 제안합니다. 사용자는 제안된 포트를 즉시 수락(Enter)하거나 다른 포트를 입력할 수 있으며, 입력받은 포트의 점유 여부를 즉시 다시 검사해 피드백을 주고 재입력을 유도하는 초경량 유효성 검증 루프를 구동합니다.
        - 비밀키(SHIM_SECRET_KEY) 처리: 최초 구동 시 비밀키 직접 입력 프롬프트를 표출하되, 입력을 건너뛰고 엔터(Enter)를 입력하면 자동으로 64자의 임의 랜덤 키를 생성하여 `data/secret.key`에 저장 및 `os.environ` 주입 후 FastAPI 구동
        - 보안 위협 제거 (개발 데이터 격리): 빌드 스크립트(`build_portable.ps1`) 및 PyInstaller 스펙에서 개발용 로컬 DB(`shim_internal.db`) 및 로컬 비밀키 복사 단계를 완전히 배제. 최초 구동 시 DB 및 스키마 자가 복구/시딩 메커니즘 활용
    - **다중 워커 설정 캐시 최적화**: 다중 프로세스 구동 환경에서 인메모리 캐시 불일치 위험을 완전히 방지하기 위해, 설정 테이블 조회 캐시를 전면 제거하고 DB에서 매번 직접 읽어오도록 처리 단순화 (로컬 SQLite의 읽기 속도가 극도로 빠르므로 복잡한 동기화 기법 불필요)
    - **배포용 Docker 이미지 경량화**: 배포용 Docker 이미지 빌드 시 `COPY . .` 방식을 피하고, `requirements.txt`와 핵심 소스 폴더(`src/`)만 명시적으로 선택 복사하여 이미지 용량을 최소화하고 개발/테스트 도구 및 문서 파일 등의 유출을 원천 방지
- **보안 및 인증**:
    - 세션 만료 정책 강화 및 쿠키 관리 (중복 로그인 방지는 무상태 JWT 인증 방식의 단순함을 깨고 데이터베이스 세션 테이블 등 복잡한 상태 관리를 유발하므로 구현 대상에서 제외)
    - FastAPI Dependency를 활용한 보다 엄격한 RBAC(Role-Based Access Control) 구조 공통화
- **테스트 커버리지**: 비즈니스 로직(연차 계산)에 대한 단위 테스트 강화 및 CI 자동화 검증
