# 향후 개선계획 (Product Roadmap)

이 문서는 SHIM 프로젝트의 중장기 발전 방향과 차기 버전의 백로그를 관리합니다. 300명 규모 및 5년 운영 수준의 소규모 폐쇄망 구동 환경에 필요한 최적의 가성비와 슬림한 포터블 배포 철학(Zero-Configuration)에 맞춰 계획을 현실적으로 조정했습니다.

---

## 🎯 1. 개발 및 운영 원칙
- **Minimalism (초경량성)**: 외부 환경이나 추가 의존성 없이 장기 구동이 가능하도록 외부 종속성을 철저히 제한합니다.
- **Lightweight Portable (슬림한 배포)**: 포터블 바이너리(`SHIM_Portable.exe`)의 기동 속도와 런타임 성능을 최적화하기 위해, 구동에 불필요한 서드파티 라이브러리 및 임포트 의존성을 전면 배제하여 순수하게 유지합니다.
- **Verification**: 모든 기능 추가 시 `tools/scripts` 내 검증 시나리오를 동기화하여 안정성을 보장합니다.
- **Consistency**: 기존의 시간 정책(30/60/120분 단위)과 Dense UI 디자인 시스템의 고유 정체성을 준수합니다.

## 4. 모던 ERP 비교 분석 및 개선 제안

### 4.1 분석 목적 및 비교 대상

SHIM 프로젝트가 현재 개발 중인 방향이 모던 ERP들의 휴가 관리 방안과 어떻게 다르고, 어떤 점이 고려 사항인지를 체계적으로 정리하여 향후 로드맵 수립의 기초 자료로 활용합니다.

| 계층 | 대표 솔루션 | 특성 |
|:---|:---|:---|
| **글로벌 엔터프라이즈** | Workday, SAP SuccessFactors | 대규모 조직, 복잡한 글로벌 컴플라이언스 |
| **글로벌 SMB SaaS** | BambooHR, Personio | 중소기업 특화, 뛰어난 UX, 클라우드 네이티브 |
| **한국 특화 SaaS** | 시프티(Shiftee), 플렉스(flex) | 한국 노동법/연차 촉진제도 등 로컬 규정 대응 |

---

### 4.2 SHIM의 포지셔닝 분석

SHIM은 모던 ERP와 **같은 시장에서 경쟁하지 않는** 독자적인 포지션을 점유하고 있습니다:
- **모던 ERP 방향**: 더 많은 기능 → 더 넓은 통합 → 더 깊은 AI
- **SHIM 방향**: 더 적은 의존성 → 더 좁은 초점 → 더 강한 자율성

> **핵심 성공 기준**: "폐쇄망 현장 PM이 3분 안에 '오늘 누가 쓸 수 있는 인력인가'를 파악할 수 있는가"

### 4.3 비교 축별 심층 분석

#### 배포 및 인프라
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **배포 모델** | 클라우드 SaaS (인터넷 필수) | 로컬 SQLite + 포터블 EXE |
| **초기 설정 비용** | 계약 → 온보딩 → 설정 (수주~수개월) | 폴더 복사 → 더블클릭 (수 분) |
| **인프라 의존성** | 클라우드 서버, CDN, DB 서버 | **없음** (Zero-Configuration) |
| **오프라인 운영** | ❌ 불가 | ✅ 완전 지원 |
| **데이터 주권** | 벤더 클라우드에 저장 | 로컬 PC 내 물리 파일 |

#### 다중 조직 관리
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **다중 회사 지원** | Multi-Entity 라이선스 (별도 비용) | ✅ 기본 내장 (Company/Team 배지) |
| **팀 간 가시성** | 조직도 기반 계층형 | 3단계 공유 수준 (none/team/company) |
| **컨소시엄 지원** | 설계 미고려 | ✅ 핵심 설계 목표 |

#### 연차 차감 엔진 정밀도
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **차감 단위** | 일/반일 (일부: 시간 단위) | 30/60/120분 정밀 단위 |
| **점심시간 자동 제외** | 일부 지원 | ✅ 기본 내장 |
| **비차감 구분 (공가/출장)** | 별도 부재 유형 모듈 | ✅ `is_deductive` 플래그로 통합 |
| **정책 스냅샷** | ❌ (변경 시 소급 영향) | ✅ 신청 시점의 정책 보존 |

#### 결재 워크플로우
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **워크플로우 복잡도** | 다단계 (팀장→부장→HR) | **단선 결재** (1단계) |
| **자동 라우팅** | AI 기반 스마트 라우팅 | RBAC 기반 (TEAM_LEAD/PM) |
| **셀프 결재 방지** | 일반적으로 지원 | ✅ 팀장 셀프 결재 금지 |
| **PM 자동 승인** | 커스텀 설정 필요 | ✅ 기본 내장 |

#### 보안 및 개인정보 보호
| 비교 항목 | 모던 ERP/SaaS | SHIM |
|:---|:---|:---|
| **인증** | OAuth2/SSO/MFA | JWT (HttpOnly Cookie) |
| **PII 보호** | 서버 사이드 암호화 + 접근 제어 | ✅ Fernet 대칭 암호화 (`EncryptedString`) |
| **감사 추적** | 기본 제공 | ✅ Actor 스냅샷 포함 감사 로그 |
| **세션 무효화** | 서버 사이드 세션 관리 | ✅ `token_version` 기반 즉시 만료 |

### 4.4 의도적 제외 항목 vs 잠재적 격차

#### 의도적으로 제외한 것 (설계 철학에 부합하므로 추가하지 않음)
| 제외 항목 | 모던 ERP에서의 역할 | SHIM이 제외한 이유 |
|:---|:---|:---|
| 급여 연동 | 연차→급여 자동 정산 | 인사 ERP 범위. SHIM은 가시성 도구 |
| 다단계 결재 | 부장→HR→이사 순차 승인 | 복잡도 증가. 단기 프로젝트 팀에 불필요 |
| AD/LDAP/SSO | 기업 인증 인프라 연동 | 폐쇄망에 AD 서버가 없는 경우가 다수 |
| 무거운 RDBMS | MySQL/PostgreSQL 마이그레이션 | 포터블 배포 철학과 상충 |

#### 잠재적으로 고려할 만한 격차
| 영역 | 현황 | 비고 |
|:---|:---|:---|
| **알림 체계** | 직접 접속 확인만 | 브라우저 알림/폴링 배지로 폐쇄망 대응 가능 |
| **접근성** | 명시적 ARIA/키보드 미구현 | 공공기관 확장 시 필요 |
| **API 개방성** | 내부 API만 | 읽기 전용 API로 확장성 확보 가능 |
| **다국어** | 한국어 전용 | 다국적 컨소시엄 대응 |

### 4.8 최종 평가

SHIM은 모던 ERP가 커버하지 못하는 **폐쇄망/컨소시엄/제로컨피그** 니치 시장에서 대체 불가능한 가치를 제공하고 있습니다.

기능 확장 시에는 반드시 아래 원칙을 견지해야 합니다:
1. **외부 의존성 추가 금지** — 폐쇄망 운영 철학 유지
2. **포터블 바이너리 무결성** — 신규 기능이 EXE 크기/기동 속도에 미치는 영향 검증
3. **Dense UI 정체성 준수** — 기존 디자인 토큰 체계 활용, 일관된 시각 언어 유지
4. **핵심 질문에 충실** — "오늘 누가 쓸 수 있는 인력인가"를 3분 안에 답할 수 있는가
