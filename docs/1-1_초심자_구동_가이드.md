# 초심자 구동 가이드 (Quick Start Guide)

이 문서는 SHIM 프로젝트를 처음 접하는 사용자가 **10분 이내에 시스템을 성공적으로 구동**할 수 있도록 돕는 실무 가이드입니다.

---

## 🛠️ 환경별 실행 로드맵

### 1. 로컬 개발 환경 (Local / venv)
가장 빠르게 코드를 실행하고 UI를 확인하고 싶을 때 사용합니다.

1.  **가상환경 활성화**:
    ```powershell
    # Windows PowerShell 기준
    python -m venv .venv
    .venv\Scripts\Activate.ps1
    ```
2.  **의존성 설치**:
    ```powershell
    pip install -r requirements.txt
    npm install
    ```
3.  **서버 실행**:
    ```powershell
    # Tailwind 빌드와 Uvicorn 서버를 동시에 실행합니다.
    npm run dev
    ```
4.  **접속**: `http://localhost:9090` (또는 터미널에 표시된 포트) (관리자 계정: `admin / 0000`)
5.  **상태 확인**: 같은 주소의 `/health`가 `{"status":"ok"}`를 반환하는지 확인합니다.

### 2. 운영 환경 (Production / Docker)
운영 환경이나 컨테이너 환경에서 실행할 때 사용합니다.

1.  **보안·시간대 설정**: `infra/docker/.env.example`을 루트의 `.env`로 복사하고 `SHIM_SECRET_KEY`를 설정합니다. `SHIM_TIMEZONE`은 기본 `Asia/Seoul`이며 해외 배포 시 IANA 이름으로 변경합니다. 잘못된 이름이면 기동이 중단됩니다. (상세 내용은 [백업/유지보수 가이드](1-2_백업_복구_유지보수_가이드.md) 참조)
2.  **이미지 빌드**:
    ```powershell
    docker build -f infra/docker/Dockerfile -t shim:latest .
    ```
3.  **컨테이너 가동**:
    ```powershell
    docker compose -f infra/docker/docker-compose.yml up -d
    ```
4.  **상태 확인**: `http://localhost:8000/health`가 `{"status":"ok"}`를 반환하는지 확인합니다. API 문서는 기본 비공개이며 개발 환경에서만 `SHIM_ENABLE_OPENAPI=true`로 활성화합니다.

> [!WARNING]
> 운영 키 유출·분실이 의심되면 먼저 서비스를 중지하고 DB, 현재 키와 설정 파일을 함께 보존하십시오. 검증된 로테이션 도구가 제공되기 전에는 키를 수동 변경하거나 재생성하지 말고 유지보수 담당자에게 인계하십시오.

### 3. 폐쇄망 환경 (Portable / No-install)
인터넷이나 Docker 설치가 불가능한 독립형 PC에서 실행할 때 사용합니다.

- **가이드**: `portable/README_PORTABLE.md` 참조
- **핵심**: 빌드된 `dist/SHIM_Portable_v<버전>_<빌드시각>.zip`을 복사해 전체 압축을 푼 후 `SHIM_Portable.exe`를 실행합니다.

## 🧪 테스트 데이터 입력 (Seeding Test Data)

개발 및 테스트 편의를 위해 샘플 데이터를 데이터베이스에 채워 넣을 수 있습니다.

> [!TIP]
> 기존 데이터베이스 파일 및 모든 데이터(사원 목록, 연차 신청, 마스터 설정 등)를 완전히 삭제하고 깨끗한 상태에서 새 데이터로 다시 채워 넣으려면 스크립트 실행 시 `--reset` 인자를 추가하십시오.
> ```powershell
> python tools/scripts/seed_test_data.py --reset
> ```

### A. 로컬 환경에서 실행
가상환경이 활성화된 상태에서 프로젝트 루트 디렉토리에서 다음 스크립트를 실행합니다:
```powershell
python tools/scripts/seed_test_data.py
```

### B. Docker 환경에서 실행
Docker 컨테이너가 실행 중이거나 정의되어 있는 환경에서도 여러 방법으로 테스트 데이터를 입력할 수 있습니다:

#### 방법 1. 실행 중인 컨테이너에 직접 실행 (`docker exec` - 권장)
`shim` 컨테이너가 구동 중인 상태에서, 해당 컨테이너 내부 환경의 파이썬 인터프리터로 스크립트를 직접 실행합니다.
```powershell
# 일반 Docker 명령 사용 시
docker exec -it shim python tools/scripts/seed_test_data.py

# Docker Compose 명령 사용 시 (환경에 따라 compose yml 파일 지정)
docker compose -f infra/docker/docker-compose.yml exec shim python tools/scripts/seed_test_data.py
```

#### 방법 2. 일회성 컨테이너 실행 (`docker compose run`)
컨테이너를 백그라운드로 실행하지 않고 임시 컨테이너를 생성하여 스크립트만 구동한 뒤 자동 삭제합니다.
```powershell
docker compose -f infra/docker/docker-compose.dev.yml run --rm shim python tools/scripts/seed_test_data.py
```

#### 방법 3. 호스트(로컬)에서 직접 실행
이 방법은 권장하지 않습니다. Compose의 `SHIM_DATA_DIR`가 가리키는 호스트 경로와 로컬 스크립트의 DB 경로가 다르면 서로 다른 DB에 데이터가 입력됩니다. 먼저 아래 명령으로 실제 마운트 원본 경로를 확인하고, 반드시 같은 절대 경로를 사용해야 합니다. 일반적으로는 방법 1을 사용하십시오.
```powershell
docker compose -f infra/docker/docker-compose.yml config
```

## 🔍 문제 해결 (Troubleshooting)

| 현상 | 원인 및 해결 방법 |
|:--- |:--- |
| **포트 충돌** | 개발 환경(`npm run dev`) 및 포터블 실행 파일(`SHIM_Portable.exe`) 모두 기동 시 사용 중인 포트를 자동 감지하여 빈 포트로 자동 할당하므로 충돌 없이 구동됩니다. 터미널 출력 창에 표시되는 **`접속 주소`**(예: `http://localhost:9090` 또는 `9091`)를 확인하여 접속하십시오. |
| **접속 불가 (404/500)** | 서버 로그를 확인하세요. Docker의 경우 `docker compose logs -f` 명령어로 실시간 확인이 가능합니다. |
| **데이터 초기화 안 됨** | 로컬은 `var/data/shim_internal.db`, Docker는 `docker compose ... config`에 표시되는 `SHIM_DATA_DIR`의 실제 마운트 원본과 권한을 확인하세요. |
| **CSS 미적용** | `npm run dev`가 정상 실행 중인지, 또는 `src/static/css/tailwind.css` 파일이 생성되었는지 확인하세요. |
