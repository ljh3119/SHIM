## 🛠️ 문서 유지 및 관리 원칙 (Document Boundaries)
각 문서의 역할이 중복되지 않도록 다음의 엄격한 작성 경계를 준수합니다.

1.  **Single Source of Truth**: 동일한 정보(예: 버전 번호)는 `package.json`과 루트 `README.md`를 기준으로 동기화합니다.
2.  **과거 이력 vs 미래 계획의 엄격한 분리**: 
    - **완료된 릴리즈 이력과 산출물**은 오직 `2-1_운영_릴리즈_통합_산출물.md`에만 기록합니다.
    - **앞으로 할 일(Backlog)**은 오직 `3-1_향후_개선계획.md`에만 기록하며, 완료 시 즉시 삭제하고 `2-1`로 이관합니다. (과거 이력을 `3-1`에 중복 기록하지 마십시오)
3.  **설계서(4-1)의 현재성**: 
    - `4-1_SHIM_프로젝트_설계서.md`는 시스템의 **현재(Current) 아키텍처 상태**만을 명확히 기술합니다.
    - 기능 변경 시 즉시 갱신하며, '어떻게 변해왔는지'에 대한 변경 이력(History)은 기술하지 않습니다. (변경 이력은 `2-1`에서 관리)
4.  **역할 중심 작성**: 문서는 읽는 사람이 누구인지(Persona)를 고려하여 해당 계층의 목적에 맞게만 작성합니다.
