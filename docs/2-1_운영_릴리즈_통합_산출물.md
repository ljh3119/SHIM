### v1.9.5 (2026-07-27) - 모바일 사용자 UI 및 응답 경량화

#### 2026-07-27 모바일 사용자 UI 후속 개선 (MOB-001~006)

- **모바일·PC 응답 분리**:
  - `/user/calendar`, `/user/team-calendar`는 공통 사용자 셸만 먼저 렌더링하고 `matchMedia('(min-width: 1024px)')` 결과에 따라 모바일 JSON 또는 PC 부분 HTML을 한 번만 지연 조회합니다.
  - PC 부분 화면은 `/user/calendar/desktop-partial`, `/user/team-calendar/desktop-partial`로 분리하고, 모바일 데이터는 `/api/user/calendar-month`, `/api/user/team-calendar`에서 선택한 한 달의 필수 필드만 제공합니다.
  - 로그인, 역할, 팀·전사 공유 범위와 기존 신청·취소 API는 유지했으며 DB 스키마와 마이그레이션은 변경하지 않았습니다.
- **모바일 사용자 흐름**:
  - 공통 상단바에 44px 알림·계정 메뉴를 분리하고 긴 브랜드명 말줄임, 바깥 클릭과 `Escape` 닫기, 기존 비밀번호 변경·로그아웃 동작을 연결했습니다.
  - 팀 일정에 연·월 선택, 1월↔12월 이동, 업무일 기준 오늘 이동, 현재 달 오늘·그 외 달 1일 초기화와 일자 상한 보정을 적용했습니다.
  - 신청 내역에는 선택 연도를 표시하는 모바일 연도 선택기를 추가했습니다.
  - 개인 화면에는 7열 월간 캘린더를 추가해 빈 업무일은 기존 신청 모달, 신청일은 상세·취소 모달로 연결하고 주말·공휴일은 선택을 차단했습니다.
  - 주요 터치 영역 44×44px, 핵심 정보 14px·보조 정보 12px 기준을 적용하고 긴 팀 일정 사유는 요약 후 `전체 보기`로 확인하게 했습니다.
  - `ADMIN` 모바일은 팀 일정과 공통 현황 조회 수준만 보장하며 관리 데이터 등록·수정·삭제는 PC 범위로 유지합니다.
- **반응형·시각 정합성**:
  - 신청 내역과 결재 관리의 PC 전환점을 다른 사용자 화면과 동일한 1024px으로 통일하고, `TEAM_LEAD`와 `PM`의 퀵 액션에 권한별 `결재 관리` 진입점을 추가했습니다.
  - 퀵 액션은 중립 배경·공통 테두리·공통 제목색으로 통일하고 상태 색상과 이동 메뉴의 색상 경쟁을 줄였습니다. `연차 신청`은 키보드 조작이 가능한 버튼으로 변경했습니다.
  - `캘린더 홈으로`는 독립 카드 대신 44px 인라인 내비게이션과 수직 중앙 SVG 화살표로 통일했습니다. 입력 모달 양쪽 버튼 높이, 카드·입력 테두리와 PC 부분 화면의 이중 배경도 함께 보정했습니다.
- **성능 증적**:
  - 기존 기록의 팀 일정 초기 HTML 744,192바이트 대비 최종 자동검증 셸은 124,694바이트로 83.2% 감소했고 `<td>`는 561개에서 0개가 되었습니다. PC 팀 부분 화면은 요청 시에만 112,662바이트·62개 `<td>`로 로드됩니다.
  - 동일 자동검증 데이터에서 개인 캘린더는 PC 연간 부분 화면 1,016,537바이트 대신 모바일 셸 149,978바이트를 먼저 내려 85.2% 감소했으며, 초기 셸에는 데스크톱 연간 DOM이 포함되지 않습니다.
- **검증 증적**:
  - `tools/scripts/test_mobile_ui.py`를 smoke 목록에 등록해 비인증 접근 차단, `STAFF`·`TEAM_LEAD`·`PM`·`ADMIN` 공개 범위, 관리자 일정 제외, 1월·12월 경계, 2024·2025년 2월, 잘못된 월의 422, 경량 셸, 긴 사유 안전 직렬화, 선택 연도, 반응형 분기와 공통 UI 규칙을 검증했습니다.
  - `npm run build:css`, 전체 Python 컴파일, `verify_version_sync.py`, 모바일 표적 테스트와 `python tools/scripts/run_tests.py smoke`를 통과했습니다.

### v1.9.4 (2026-07-18) - 정식 배포 전 안정성 및 출력 보안 강화

- **Docker·릴리스 안정성**:
  - Docker는 Uvicorn을 exec 형식으로 직접 실행하며, 중복 DB 초기화를 제거해 시작은 FastAPI lifespan 한 경로로 통일했습니다. 종료 신호가 Uvicorn에 직접 전달되어 백그라운드 작업과 SQLAlchemy 엔진을 정상 정리합니다. OS 시간대는 이미지의 `ENV TZ=UTC`를 단일 기준으로 사용하고 Compose의 중복 `TZ` 설정을 제거했습니다.
  - 릴리스 순서를 버전 동기화, CSS 생성, 검사, Docker 이미지 빌드 순으로 조정했습니다. Python, npm, Compose, 버전 검사, 릴리스 테스트와 Docker 빌드는 종료 코드가 0이 아니면 즉시 중단합니다.
- **출력·입력 보안**:
  - 연차 및 감사 엑셀의 사용자 입력 문자열이 `=`, `+`, `-`, `@` 또는 탭·줄바꿈 계열 문자로 시작하면 일반 텍스트로 기록합니다. 날짜와 숫자 셀의 기존 자료형은 유지했습니다.
  - 공통 토스트 메시지는 동적 HTML 조립을 제거하고 `textContent`로 출력합니다.
  - 신청 사유는 서버와 모든 관련 입력 화면에서 500자로 제한하며, 501자 이상은 400 입력 오류로 거부합니다.
  - 예상하지 못한 연차 신청 오류는 서버 로그에만 상세 내용을 남기고 API에는 고정된 일반 오류 문구를 반환합니다.
- **데이터 일관성**:
  - 사용자별 연도 배정 행이 없을 때만 기본 연차 시간을 사용합니다. 배정 조회 오류는 더 이상 기본값으로 숨기거나 트랜잭션 잠금을 중간 해제하지 않으며 신청 전체를 롤백합니다.
  - DB 스키마와 기존 관리자 초기 비밀번호, 같은 날짜의 서로 다른 시간차 허용 정책은 변경하지 않았습니다.
- **초기 데이터·운영 문서 정비**:
  - 신규 DB와 테스트 시드가 생성하는 2020~2050년 공휴일에 2026년부터 제헌절(7월 17일)을 포함하고, 토·일요일과 겹치면 다음 비공휴일을 대체공휴일로 등록하도록 보완했습니다. 기존 운영 DB는 자동 변경하지 않습니다.
  - Docker 운영 예시는 `SHIM_SECRET_KEY`, `SHIM_TIMEZONE`, `SHIM_SECURE_COOKIE`의 역할과 `.env` 주입 방법을 실제 Compose 형식에 맞게 정리했습니다. 비밀키를 잃거나 교체하면 기존 암호화 데이터와 세션에 영향이 있으므로 데이터 디렉터리와 함께 백업하도록 명시했습니다.
  - 루트·포터블 README를 현재 v1.9.4 실행 경로, 데이터 위치, CSS 생성, 릴리스 검사 및 포터블 산출물 구조에 맞춰 정비했습니다.
- **의존성 위험 수용**:
  - `python-jose`가 의존하는 `ecdsa 0.19.2`의 [PYSEC-2026-1325](https://osv.dev/vulnerability/PYSEC-2026-1325)는 ECDSA 서명·키 생성·ECDH의 타이밍 측면 채널이며 현재 수정 버전이 없습니다. SHIM은 JWT를 `HS256` 하나로 제한하여 해당 실행 경로를 사용하지 않습니다.
  - 인증 회귀 테스트로 `HS256` 고정과 다른 알고리즘 거부를 확인합니다. JWT 알고리즘을 변경하거나 수정 버전이 공개되면 [GHSA-wj6h-64fc-37mp](https://github.com/tlsfuzzer/python-ecdsa/security/advisories/GHSA-wj6h-64fc-37mp)를 기준으로 재검토합니다.
- **검증 증적**:
  - Python 컴파일과 엑셀 수식 방지, 신청 사유 500/501자 경계, 배정 조회 오류 전파·전체 롤백, HS256 고정 표적 테스트를 통과했습니다.
  - 공휴일 회귀 테스트와 빈 임시 DB 초기화를 통해 2026년 7월 17일 제헌절 및 2027년 7월 19일 대체공휴일 생성을 확인했습니다.
  - 버전 동기화, 운영·개발·테스트 Compose 설정 해석, README 상대 링크·코드 블록 및 Git diff 형식 검사를 통과했습니다.
  - 가상환경 기준 전체 릴리스 검사를 371.2초에 통과했습니다. 통합 CASE 30개, 정상 종료, 중복 실행과 메모리 1,000회 검사를 포함하며 API RSS `+5.45 MB`, 반복 엑셀 RSS `+6.61 MB`, Python heap `+0.27 MB`를 기록했습니다.
  - `pip check`와 `npm audit`는 각각 의존성 불일치 없음, 취약점 0건으로 통과했습니다. `pip-audit`는 위에서 수용한 `ecdsa 0.19.2 / PYSEC-2026-1325` 한 건만 재확인했습니다.
  - 릴리스 후보 검증용 Docker 이미지 `shim:1.9.4`와 `shim:latest`를 생성했습니다. 이미지 ID는 `sha256:f8529aa55105a03cff80a8e6f85f73cccf16f4c9c2850efce676ca165cb28645`, 크기는 68,938,850바이트입니다.
  - Docker 실기동에서 루트·문서·CSS HTTP 200, 내장 버전 1.9.4, 종료 코드 0, Uvicorn 정상 종료, SQLAlchemy 엔진 dispose와 WAL/SHM 0건을 확인했습니다.
  - 릴리스 후보 포터블 산출물은 `dist/SHIM_Portable_v1.9.4_20260718-145728.zip`이며 25,104,609바이트, SHA-256은 `36A178A1BD1610C0AF5E062D8D6B44DB745D82C457AF091EBCA4FA247930FC9B`입니다.
  - 포터블 EXE 실기동에서 루트·문서·CSS HTTP 200, 내장 버전 1.9.4, 종료 코드 0, 정상 종료와 엔진 dispose를 확인했습니다. ZIP 내부 운영 DB·비밀키·백업 파일과 종료 후 WAL/SHM은 모두 0건이었습니다.
  - 위 후보 산출물은 제헌절 시딩과 최종 운영 문서 정비 전에 생성했습니다. 정식 배포용 Docker 이미지와 포터블 ZIP은 현재 소스 커밋을 기준으로 다시 빌드하고 이미지 ID·크기·해시를 교체 기록해야 합니다.

### v1.9.3 (2026-07-14) - 시간대 단일화, 리포지토리 슬림화 및 배포 문서 정비

- **2026-07-13 리포지토리 슬림화 후속 정비**:
  - 테스트용 HTTP 클라이언트를 `httpx==0.26.0`으로 통일하고 `requests` 직접 의존성을 제거했습니다. `httpx`는 `requirements-dev.txt`로 이동해 운영 의존성과 개발·테스트 의존성의 경계를 명확히 했습니다.
  - 30분 시간 선택지 생성을 `range` 기반으로 단순화하고, `24:00`은 서버 정책상 유효한 업무 종료 선택에만 표시하도록 관리자 UI를 정리했습니다.
  - 연차 시간 축약 표시 함수의 양수·음수 중복 계산을 제거하면서 `None`, 0, 소수 시간, 음수 정수일과 혼합시간 출력 회귀 테스트를 추가했습니다.
  - 메모리 테스트의 RSS 기준점을 워밍업 이후로 옮기고 API 반복과 Excel 반복 구간을 분리했습니다. 테스트 종료 시 SQLAlchemy 엔진을 dispose한 뒤 임시 DB를 삭제하도록 수정해 Windows 파일 잠금을 해소했습니다.
- **2026-07-14 시간대 단일화 및 날짜 오류 정비**:
  - 배포 설정을 `SHIM_TIMEZONE` 하나로 통합하고 기본값을 `Asia/Seoul`로 고정했습니다. 시작 시 IANA 이름을 `ZoneInfo`로 검증·캐시하며 잘못된 값은 기동 실패로 처리합니다.
  - SQLite Naive UTC 저장 형식과 API ISO timestamp 형식은 유지했습니다. `AwareDateTime`은 저장·쿼리 바인딩 시 timezone-aware 값만 허용하고, 기존 SQLite 조회값에는 UTC tzinfo를 부여합니다. 스키마 및 운영 데이터 마이그레이션은 수행하지 않았습니다.
  - 감사·일일 통계의 사업장 자정 경계를 UTC로 변환하도록 중앙화해 DST 전환일의 23/25시간을 반영했습니다. 감사 화면과 엑셀은 동일한 쿼리 경계를 공유합니다.
  - 화면의 브라우저 현지 시간 자동 변환과 중복 `Z` 추가를 제거했습니다. 공통 `YYYY-MM-DD` 파서를 정적 스크립트로 분리해 서반구 브라우저에서도 업무 날짜가 전날로 이동하지 않게 했으며, 알림의 잘못된 ISO 값은 `Invalid Date` 대신 빈 값으로 처리합니다.
  - 알림 정리는 사업장 시간 02:00을 기준으로 예약하며 DST 누락 시 직후 첫 유효 시각, 중복 시 첫 번째 시각을 선택하고 UTC끼리 대기 시간을 계산합니다.
  - 운영 의존성에 `tzdata==2026.2`를 추가하고 Docker OS는 `TZ=UTC`, 앱은 `SHIM_TIMEZONE`으로 분리했습니다. 포터블 빌드에는 `--collect-data tzdata`를 추가했습니다.
- **문서·버전 관리 정비**:
  - 운영·포터블·설계 문서를 실제 Docker 경로, 정상/강제 종료 구분, 사업장 시간대 계약과 현재 마이그레이션 정책에 맞게 정리했습니다.
  - 버전 동기화 도구가 `package-lock.json`과 운영·개발·테스트 Compose 기본 이미지 태그를 모두 갱신·검사하도록 보완했습니다.
  - 포터블 빌드는 로컬 임시 폴더에서 완성한 뒤 버전·빌드시각이 포함된 불변 ZIP 한 파일만 게시하도록 변경했습니다. 외부 명령 실패를 즉시 차단하고 운영 `var/data`는 빌드 입력에서 제외합니다.
- **검증 증적**:
  - 일반 회귀 테스트, graceful shutdown 테스트, `pip check`, `httpx` 차단 상태의 운영 앱 import 및 버전 동기화 검사를 통과했습니다.
