## 2) 핵심 기능/구조 반영 요약

- 연차 이력은 `Leaves.snapshot_*` + `status` + `rejection_reason` 기반 저장
- 승인 워크플로우는 `SystemSettings.is_approval_required`로 제어
- 시간 정책은 `SystemSettings.time_granularity_minutes`, `work_start_minute`, `work_end_minute`, `lunch_start_minute`, `lunch_end_minute`로 제어
- 병합 정책(`LeavePolicies`)은 운영 단순화 방침으로 제거
- 관리자 화면에서 상태 변경, 승인 설정, 수동 DB 백업 수행 가능

## 3) 운영 정책: 신청 취소 vs 삭제

- `CANCELED`: 행 유지 + 상태만 변경(기록 보존)
- 삭제: 행 물리 삭제(복구 어려움)

권장 기준:

- 일반 운영은 취소 우선
- 삭제는 테스트/중복 오기입 같은 예외 상황에 한정
- 관리자 화면 라벨은 "영구 삭제(복구 불가)" 톤으로 유지

## 7) 운영 규모 성능 리허설 기록 항목

실제 운영 DB를 직접 변경하지 않도록 운영 유사 복제 DB 또는 별도 `SHIM_DATA_DIR`에서 서버를 기동한 뒤 `tools/scripts/performance_rehearsal.py`로 측정합니다.

- 측정일시:
- 실행 환경: Docker / 로컬 / 포터블
- DB 기준: 운영 복제본 / 리허설 DB / 기타
- 데이터 규모: 사용자 수, 연차 신청 건수, 측정 연도
- 측정 대상: 관리자 대시보드, 타임라인, 월간 캘린더, 연간 캘린더
- 결과: 평균/최대 응답시간, 3초 기준 초과 여부
- 조치 여부: 쿼리/인덱스 보강 필요 여부
