## 📈 1. 릴리즈 이력 (Release History)

### v1.4.0 (2026-05-18) - 관리자 사용성 및 시스템 안정성 최종 강화
- **핵심 연차 신청 로직 복구**:
  - 누락되었던 `POST /user/leave` 엔드포인트를 v1.4.0 표준에 맞춰 완전 복구.
  - **PM 자동 승인**: PM 권한 사원이 신청 시 별도 승인 절차 없이 즉시 `APPROVED` 처리.
  - **정밀 시간 계산**: 점심시간 자동 제외 및 시스템 설정 시간 단위(30/60/120분) 엄격 준수.
  - **무결성 검증**: 중복 시간대 신청 차단 및 1일 8시간 초과 신청 방지 로직 강화.
- **감사 로그(Audit Logs) 고도화**:
  - 기존 마스터 화면 하단에 있던 감사 로그를 독립된 전용 페이지(`/admin/audit`)로 분리.
  - 엑셀 다운로드 기능 추가 및 액션/대상 정보의 100% 한글화 적용 (예: `USER_UPDATE` -> `사원 정보 수정`).
  - 서버 측 LIMIT/OFFSET 페이징(50건 단위) 적용으로 대량 로그 조회 시 성능 보장.
  - 연차 삭제 등 주요 액션 시 사원명과 날짜를 명시하여 추적성(Traceability) 대폭 강화.
- **사원 관리 UI/UX 최적화**:
  - 사원 목록의 작업 버튼들을 콤팩트한 **아이콘 버튼 4종**(수정, 비밀번호 초기화, 상태 전환, 삭제)으로 개편하여 가로 스크롤 문제 해결 및 레이아웃 안정성 확보.
- **타임라인 성능 개선**:
  - 신청 타임라인에 서버 측 페이징(50건 단위)을 도입하여 연차 데이터 누적 시 브라우저 렌더링 부하 원천 차단.
- **검증 결과**: 
  - `run_remaining_tests.py` 시나리오(PM 자동 승인, 사원 대기, 삭제 감사 로그) 전면 통과 (Status: **PASS**)
  - 신규 `seed_test_data.py`를 통한 대규모 조직 데이터 연동 확인 완료.

### v1.3.3 (2026-05-14) - PM 권한 확장 및 전사 문서 현대화
- **PM 권한 및 결재 모델 혁신**:
  - **전사 결재 권한**: PM 역할 사용자에게 전사 모든 팀의 `PENDING` 건 조회 및 결재 권한 부여.
  - **중복 결재 방지**: 결재 처리 시점의 상태값(`status == 'PENDING'`) 재검증 로직을 통한 데이터 충돌 차단.
  - **결재 UI 개선**: 결재 목록에 '팀명' 열을 추가하여 전사 신청 건에 대한 식별력 강화.
- **팀 캘린더 및 대시보드 고도화**:
  - **범용 팀 조회**: 소속 회사가 달라도 동일 '팀' 명칭을 사용하면 상호 조회가 가능하도록 로직 개선.
  - **PM 전사 뷰**: PM은 팀 캘린더에서 시스템 내 모든 사용자의 현황을 관리자와 동일하게 조회 가능.
  - **UI 통합**: 팀 캘린더의 필터 영역과 본문 영역을 하나의 패널로 통합하고 레이아웃 정밀 튜닝.
  - **개인화**: 대시보드 인사말에 '직급' 정보 노출 및 팀별 동적 타이틀(`OOO팀 캘린더`) 적용.
- **문서 체계 전면 리팩토링**:
  - **수석 테크니컬 라이터 관점 적용**: `README.md` 및 `docs/` 전 산출물의 논리 구조와 전문성 강화.
  - **신규 가이드**: `portable/README.md`(개발자용) 신설 및 전체 문서 인덱스 재구축.
- **브랜딩 표준화**:
  - 시스템 초기 설치 시 적용되는 기본 브랜딩 값을 `쉼(SHIM) 프로젝트 개발 운영 / SHIM / S`로 재정립.

## 🏗️ 2. 핵심 구현 기준 요약

### 데이터 및 워크플로우
- **신청 기록**: `Leaves.snapshot_*` 필드를 통해 신청 당시의 정책/시간 정보를 보존합니다.
- **승인 제어**: `SystemSettings.is_approval_required` 값에 따라 전사 승인 프로세스를 토글합니다.
- **시간 정책**: 시작/종료 시각 입력 기반이며, 정책 단위(30/60/120분)에 따른 경계값 검증을 수행합니다.

### 운영 및 유지보수 정책
- **신청 취소 vs 삭제**: 
  - 기록 보존이 필요한 경우 `CANCELED` 상태로 전환(권장)
  - 테스트 데이터 또는 오기입 데이터만 물리적 `삭제` 수행
